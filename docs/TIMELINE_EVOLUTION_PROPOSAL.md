# 时间轴演进方案

## 当前状态

当前 `EditorTimeline` 以固定顺序渲染时间刻度、主视频波形、视频帧带、分镜组、分镜五条带。各条带都用时长百分比定位，缩放只改变容器最小宽度；这适合首版，但不适合继续加入外部音频、字幕、蒙版或更多分析轨道。

## 调研结论

### OpenReel

- `apps/web/src/stores/timeline-store.ts` 将 `pixelsPerSecond`、横纵滚动、视窗尺寸、播放头、缩放、轨道高度与坐标换算集中到独立状态层。
- `components/editor/timeline/TimeRuler.tsx` 根据当前可见范围和缩放密度生成刻度，并在拖动时用 `requestAnimationFrame` 节流定位。
- `TrackLane.tsx` 只负责单轨绘制和该轨交互；媒体、音频、文字、图形等轨道统一使用 `time × pixelsPerSecond` 作为坐标。
- 该模式服务于完整多轨剪辑器，轨道增删、混音、素材拖放和转场都不属于 AisenLens 当前范围。

### OpenCut

- `timeline/types.ts` 以明确的轨道类型与时间范围组织视频、音频、文字、图形和效果；时间内部采用整数媒体时间。
- `timeline/components/timeline-ruler.tsx` 只渲染可见区间附近的刻度，缩放、定位、播放头分别由 controller/hook 协调。
- `timeline/zoom-utils.ts` 以光标或播放头为缩放锚点，缩放后保持用户关注的时间点不跳动。
- 其场景、多轨、素材与渲染模型对单视频拉片过重，只借鉴坐标、虚拟绘制、交互控制器分离的原则。

### 旧 AisenLens

- `features/waveform/waveform-controller.js` 已验证“围绕鼠标点缩放、拖动平移、播放时跟随”的单媒体视窗模型。
- 旧项目没有可直接复用的多轨时间轴；其蒙版属于预览画面叠加，不应当被误建模为媒体剪辑轨道。

## AisenLens 决定

不引入剪辑器的 `Track/Clip`、多媒体合成、音频混音、轨道拖放或转场。建立**单视频研究时间轴**：所有轨道共享一条只读时间坐标和播放头，领域数据继续由分镜、分组、标记、未来字幕和未来注释等实体独立保存。

### 轨道层级

1. **标尺与标记层**：自适应刻度、播放头、循环/选区（后续）、项目标记。
2. **媒体概览层**：主视频波形、未来外部音轨波形、视频帧带。
3. **研究结构层**：分镜组范围、分镜边界和分镜块。
4. **可选信息层**：字幕/转写、蒙版或构图提示、AI 候选、筛选命中。

蒙版默认是预览的构图辅助信息；只有它拥有明确起止帧时，才显示为“构图提示区间”，不能将永久三分法等全局设置伪装成时间片段。

### 统一视图状态

新增 `features/timeline`，由 `useTimelineViewport` 或 Zustand store 管理以下非领域临时状态：

```ts
interface TimelineViewportState {
  pixelsPerSecond: number;
  scrollLeft: number;
  viewportWidth: number;
  trackVisibility: Record<TimelineTrackId, boolean>;
  trackHeights: Partial<Record<TimelineTrackId, number>>;
}
```

- 提供唯一的 `timeToPx()`、`pxToTime()`、`visibleRange()` 和 `seekFromPointer()`；所有轨道禁止再各自做百分比换算。
- 以光标位置或播放头为缩放锚点；滚轮缩放、拖动平移、播放头自动跟随可分阶段加入。
- 标尺只渲染可见区间和缓冲区的刻度；帧带、波形在当前缩放密度下采样，避免长视频渲染大量 DOM 节点。
- 轨道可显示/隐藏，非领域的轨高与可见性写入本地工作区偏好，不进入项目备份或恢复快照。

### 领域轨道描述符

首版不把轨道写进项目数据。UI 使用固定且可扩展的描述符，将已有领域数据投影为轨道：

```ts
type TimelineTrackId =
  | "ruler"
  | "primary-audio"
  | "external-audio"
  | "video-frames"
  | "groups"
  | "shots"
  | "subtitles"
  | "guides";
```

未来真正导入外部音频时，再新增独立 `AudioAsset` 领域实体（稳定 ID、文件引用、起止帧、音量/静音等必要研究属性），而不是在时间线组件内维护音频文件状态。

## 建议实施顺序

1. **P1：坐标与布局重构**：从 `EditorTimeline` 抽取视窗控制、标尺、播放头和轨道容器；保持当前五条带与行为不变。**已完成**。
2. **P2：缩放与导航体验**：自适应刻度、按钮/快捷键缩放、以指针为锚点、拖动平移、播放头跟随开关。
3. **P3：轨道管理**：添加紧凑轨道头、显示/隐藏、轨高调整；默认只露出当前已有轨道。**已完成**。
4. **P4：研究轨道增强**：标记独立成行，分组/分镜轨支持更清晰的层级和筛选命中高亮。
5. **P5：按需接入新数据**：字幕轨、范围型构图提示轨；外部音频需要先单独确认领域数据与媒体权限策略。

## 验收重点

- 同一时间点在标尺、波形、帧带、分组、分镜和未来轨道中的 x 坐标严格对齐。
- 放大、缩小和横向滚动后，点击任意轨道都定位到正确时间。
- 长视频不因刻度、波形或缩略图数量导致明显卡顿。
- 隐藏轨道、轨高、滚动和缩放是工作区偏好，不污染项目导出、备份或自动恢复。

## P1 实施记录

- 新增 `features/timeline/hooks/useTimelineViewport.ts`，集中维护缩放、横向滚动、可见时间范围及时间/像素换算。
- 新增通用 `TimelineRuler` 与 `TimelineTrack`；标尺仅生成可见时间范围内的刻度，现有轨道共享一个横向滚动内容区域。
- 主音频波形、视频帧带、分组范围、分镜和标记均已改用同一个 `timeToPx()` 坐标，不再以各自百分比计算横向位置。
- 当前 Ctrl + 滚轮继续控制缩放，点击各轨道、帧带定位、标记跳转、分镜选择与边界拖动保持原有职责。
- 已执行 `pnpm.cmd run build`，通过；仍需在真实短视频和长视频中手动检查缩放、滚动与边界拖动。

## P3 实施记录

- 新增 `useTimelineTrackPreferences`，以 `localStorage` 保存轨道显隐与高度，不写入项目领域数据、备份或恢复快照。
- 新增 `TimelineTrackHeader`，为音频、帧带、标记、分组和分镜提供紧凑名称、显隐按钮与高度拖拽控制。
- 标记从标尺叠层拆为独立轨道；五类现有时间内容继续共享统一时间坐标。
- 隐藏轨道保留紧凑标题行，用户可随时恢复显示；轨道高度限制在 `20-160px`，避免布局被拖坏。
- 已执行 `pnpm.cmd run build`，通过；浏览器手动验收仍需检查窄窗口、隐藏轨道后的滚动高度和拖拽手感。

## P4 实施记录

- 分组轨道显示组名、镜号范围与总时长；点击范围会定位到该分组的首镜，并打开右侧分组详情。
- 分镜轨显示镜号和边界，当前分镜保持强调；筛选条件存在时，命中分镜高亮，未命中项弱化但不从时间轴删除，保留完整时间结构。
- 必填分析尚未完成的分镜以黄色状态点提示；完成度仍由编辑器既有模板校验逻辑统一计算，时间轴不维护副本。
- 分镜列表的筛选状态提升至编辑器工作区，列表和时间轴共用同一份 `findMatchingShotIds()` 派生结果，避免两处筛选规则漂移。

## P4 标记轨增强记录

- 标记轨增加类别颜色开关；显示偏好仅停留在编辑器工作区，不改变项目内的标记数据。
- 点击标记会定位播放头、选中所属分镜并展开既有标记面板；面板和轨道共享当前选中标记状态。
- 当前分镜所属标记加粗并在足够缩放密度下显示名称；选中标记始终显示名称和批注提示。
- 筛选只隐藏对应类别的视觉投影，不移除标记实体或重排时间轴坐标。

## 帧带真实帧采样记录

- 帧带不再固定平铺预生成缩略图；每个约 80px 的格子对应一个由当前 `pixelsPerSecond` 换算出的明确视频帧。
- 仅请求当前可见时间范围及一屏缓冲范围内的帧。命中 IndexedDB 派生缓存时立即显示；缺失时按帧顺序用离屏 video 与 Canvas 解码、写入缓存并更新格子。
- 缩放和横向平移都会重新计算真实帧槽位；缩小时减少槽位，放大时只补齐当前看片区域，避免长视频全量解码。
- 后续可加：请求取消、并发优先级、缓存容量上限和邻近帧预取；这些属于性能优化，不影响当前帧号与时间轴坐标的一致性。

## 帧带解码队列优化记录

- 缩放连续变化时使用 150ms 防抖，避免每个滚轮事件都启动一批解码。
- 采用单一可抢占队列和复用的离屏 `video`，新视窗版本会让旧队列停止发布、停止继续写缓存。
- 可见范围内的帧按距离播放头排序，单帧完成即发布到 UI；缓冲区帧在可见帧之后处理。
- 维护有限内存 Object URL 缓存，避免重复打开同一帧和无限积累缩略图资源。

## 帧带内存缓存策略记录

- Object URL 内存缓存以每个已挂载帧带的当前请求范围为准：可见范围及其缓冲范围内的帧保持可用，不再以固定 240 张作为常驻容量。
- 轨道排序导致帧带短暂重挂载时，离开请求范围的缩略图会保留 1.5 秒；重新挂载可以复用原 URL，避免浏览器图片元素引用已撤销 URL 后显示加载失败。
- 超过 1.5 秒的离屏缩略图会自动释放，并且最多保留 32 张离屏资源作为短时回退；IndexedDB 中的派生缩略图仍是长期缓存，内存释放后可直接读取，无须重复解码。

## 轨道排序记录

- 左侧轨道头可通过拖动把手调整音频、帧带、标记、分组和分镜的上下顺序，右侧轨道内容同步重排。
- 顺序与显隐、轨高一起仅保存到本地工作区偏好，不写入项目、备份或导出。
- 拖拽起点限定为左侧轨道头，避免与时间轴内的定位、分镜边界拖动和中键平移冲突。

## 分镜色块与边界编辑调整记录

- 分镜轨以中性底色表达时长与位置；选中分镜使用主强调色，播放头所在分镜使用轻量底色，筛选命中分镜增强，未命中项仅弱化而不移除。
- 必填分析未完成继续使用黄色状态点，不以整块警示色干扰时间结构阅读。
- 移除时间轴分镜块的边界拖拽手柄与拖动预览，避免与定位、选择和中键平移竞争；边界如需调整，仍在右侧“画面调整”通过首帧/尾帧精确提交。

## 分镜列表联动记录

- 当前分镜改变时，右侧分镜列表自动将对应条目滚动到最近可见位置；若它所在分组已折叠，先展开该分组。
- 当前筛选不匹配该分镜时，保留筛选结果，不自动清除或修改用户筛选条件。
- 播放头按帧进入另一分镜时，该分镜成为当前选中项；右侧分镜列表点击始终定位视频到目标分镜的首帧。
