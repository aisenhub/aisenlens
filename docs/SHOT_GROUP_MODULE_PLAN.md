# 分镜分组模块计划

## 当前目标

用项目级连续镜头分组表达场景、段落与序列，为拉片阅读和后续表格、HTML、PDF、Excel 导出提供章节结构。

## 已确认规则

- 分组是独立领域实体，保存 `kind`、标题、摘要与稳定 `shotIds`；不把分组信息写进分镜记录。
- 仅允许同一层、至少两个、在当前分镜顺序中连续的成员；任何镜头最多属于一个分组，禁止重叠与嵌套。
- 新建、自动应用、切分、合并或删除分镜后，服务会校验成员仍存在、连续且互斥；不再满足条件的分组自动移除。
- 分组不改变分镜的播放范围、分析字段或截图所有权，只提供结构化组织与导出章节。
- 场景、段落、序列是展示与导出语义，不引入剪辑器的多轨时间线或媒体合成模型。

## 实施记录

- [x] 新增 `features/group/` 的类型、连续性校验、冲突拒绝与持久化服务。
- [x] IndexedDB 新增 `shot-groups` 项目级存储，删除项目时级联清理。
- [x] 分组创建采用两段式选择：默认分镜列表不显示复选框；填写标题后点击“选择镜头”才进入选择模式，确认创建后自动退出。
- [x] “手动分镜”工具移除重复的更新截图入口，截图更新只在右侧画面面板完成。
- [x] 分镜列表按分组标题折叠；可定位与连续播放整个分组。
- [x] 分组仅可从首尾扩展或收缩，不能少于两镜、不能越过已有分组；时间线用范围色带标出分组。
- [x] 新增 `groupExportService`，将有效分组转换为包含标题、摘要、时间范围和成员镜头的导出章节数据。
- [x] 分组的摘要、范围调整与删除收纳为悬浮详情，工具面板默认只显示紧凑的类型和标题。
- [x] `pnpm.cmd run build`。

## 后续优化

1. 在分组标题中显示真实镜号范围与总时长，并加入快捷的“选择全部成员”。
2. 增加“从当前镜头到…”的范围选择和跨组移动命令；仍由领域服务统一验证。
3. 在导出模块中消费章节数据，生成带标题、摘要、镜头范围与代表图清单的实际表格文件。
4. 若未来确有需求，再设计跨层级的“序列包含场景”模型；不得将当前同层分组直接改成任意嵌套树。
