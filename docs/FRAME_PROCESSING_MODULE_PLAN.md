# 帧处理与派生缓存模块计划

## 本阶段目标

用真实视频画面替换编辑器时间线中的演示帧带，并建立可再生、与项目领域数据隔离的本地派生缓存基础。

## 已确认方案

- 使用浏览器原生 `<video>` 定位和 Canvas 编码 JPEG，不新增解码依赖；当前单主视频场景不需要多轨编辑器级 WebCodecs/Mediabunny 引擎。
- 帧位置使用整数 `frame`；缓存按项目 ID、媒体指纹和帧号识别。媒体文件变化后旧缓存不参与读取，并会在下一次采样中被替换。
- 缩略图是派生缓存，不进入分镜、项目导出或正式截图数据；首次打开按视频时长均匀采样 24 张，后续打开直接复用 IndexedDB 缓存。
- 浏览器运行期间只保存 Object URL；离开项目时统一释放，不能将 URL 或 HTMLVideoElement 写入 IndexedDB。

## 分镜首尾帧补充

- 分镜首帧和尾帧属于正式截图数据，每个引用记录在对应分镜中，不复用帧带的可再生缩略图。
- 初次打开已有项目会补采缺失边界画面；创建、自动应用、切分、合并或拖动边界后，只重新采集受影响的边界。
- 使用离屏 `<video>` 与 Canvas 采集，不能让用户正在观看的主预览视频跳帧或暂停。
- “分镜截图”面板只展示后续表格导出的代表图：默认自动使用首帧，用户可采集当前帧直接替换；首尾帧仍在画面面板中作为边界预览。
- 边界采集必须等待媒体数据可绘制；首帧不依赖必然触发的 `seeked` 事件。任务状态变化导致旧采集失效时，释放去重标记并重新调度，不能留下永久占位。
- 帧控件必须使用当前视频帧率和相邻分镜的真实边界，禁止演示用固定帧数上限；视频整体首帧、末帧为固定边界，中间分镜仅可调整共享边界以保持连续。
- 边界图采集队列不能因单张截图写入状态而取消同批任务；媒体事件监听必须先于 `src` 设置，并以超时与有限重试防止个别镜头永久停在占位状态。

## 后续边界

- 下一模块生成真实音频波形，采用同一“媒体指纹 + 可清理派生数据”的边界。
- 帧精确解码、按需高清帧、帧带缩放与自动分镜复用此服务边界；若引入 WebCodecs，必须先做浏览器能力检测和独立降级设计。
