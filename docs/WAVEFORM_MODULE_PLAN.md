# 真实音频波形模块计划

## 已确认方案

- 使用 Web Audio `decodeAudioData` 解码本地视频的音轨，以每段峰值生成最多 1,200 个波形桶；不依赖演示数组，也不持久化 `AudioBuffer`。
- 波形为派生数据，以项目 ID 和媒体指纹写入 IndexedDB。媒体变化、无音轨或浏览器无法解码时，不读取旧缓存并明确显示不可用状态。
- 当前时间线缩放仍使用全局概览波形；未来局部缩放或高密度编辑可由同一原始媒体重新生成多分辨率峰值，而不改变领域数据。

## 参考结论

- OpenReel 以高分辨率峰值派生多分辨率波形，并缓存持久化结果。
- OpenCut 以源音频摘要作为缓存单元，并在渲染时按像素密度采样。
- 旧 AisenLens 已验证峰值/RMS 分桶、处理过程让出主线程和波形视图交互；本阶段仅吸收其受限分桶原则，不复制实现。

## 修复记录（2026-08-12）

- 修复波形只显示开头部分：原始缓存可达 1,200 个桶，逐桶使用最小宽度 Flex 元素会超过时间线可视宽度；现在在渲染前按时间顺序重采样为最多 360 根等宽柱子，完整时长始终可见。
- 修复刷新或媒体元数据二次更新时重复解码：同一项目与媒体指纹的进行中请求现会合并，避免多个效果并发分析和相互覆盖缓存状态。
