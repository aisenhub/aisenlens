# C5 — 第二期：疑点引导与局部补检

状态：后续范围，未实施。第一期 C0–C4 完成后单独推进。不要让此阶段阻塞人工补切闭环，也不要在第一期放假智能按钮。

## 1. 再次研究并冻结范围

这是新增辅助识别模块，实施前必须按项目顺序完成公开解决方案 → AisenLens提案 → OpenReel → OpenCut 的相关文件研究并更新索引。前轮研究可作起点，但不能当作局部重检/低阈值指标接口已实现的证据。

优先检查现有 scene-engine 输出和 diagnostics 实际传输/保存的指标。当前 AutoShotCandidate 的 score/evidence 只证明已输出候选的数据，不能据此在未检出区间绘制真实变化曲线；diagnostics 有枚举也不证明完整逐帧曲线已可用。

## 2. C5a — 无新增检测数据的检查引导

先实现镜头时长异常提示，基于真实时长分布、上下文与明确规则。UI 用“片段较长，建议查看”，不使用“漏切概率 80%”或红色错误断言。

全是长镜头、样本过少、时长差异很小的素材不硬生成疑点。排序作为可选“建议检查”，保留按时间巡视；手工待回看优先且不被统计规则覆盖。

规则、版本、解释可追踪；每个建议可跳转、忽略或标已查看，独立于明确人工复核状态。算法产生建议不会增加巡视覆盖。

## 3. C5b — 未采用变化峰值

只有引擎真实保留对应指标后实施。候选峰值须去重、排除已存在边界/用户已拒绝同版本建议，提供峰值附近前后画面与检测器说明；不自动写草稿切点。

需要新 metrics 通道时单独设计内存/持久化预算、任务身份、配置版本和生命周期，不能全片所有 bitmap/逐帧对象塞 Zustand。用户修改边界后建议重新投影，不制造重复补切。

验收：低于采用阈值的真实峰值可展示为建议；误运动峰值可忽略；没有指标时不画假曲线。score、ratio、threshold 不转成概率。

## 4. C5c — 局部更敏感检测

用户明确选择区间并启动；现有引擎若不支持区间输入/上下文边界，先实现和验证接口，不用全片重跑冒充局部检测。

- 区间扫描需要必要前后上下文，输出只纳入所选范围；adaptive/fade 状态起始语义有测试。
- 子任务有独立 id、媒体身份、配置快照、父草稿revision、范围、取消/错误状态。
- 不修改全局生产预设、不覆盖原自动检测任务原始证据、不自动替换人工边界。
- 返回后只展示新增建议，接受一个或明确接受一组才派发草稿命令。
- 扫描中修改草稿时比较 revision，去重并重新预览；不得用旧结果覆盖。
- 取消/失败保持原草稿；支持局部重试，不能清空整片结果。

## 5. 独立验收

使用确定性漏切、快速运动误峰值、真正长镜头、淡变、区间端点等素材，记录建议准确性与人工修复耗时。测试人数/样本不足时仅报告观察，不宣称统计提升。

允许第一期长片校准依靠巡视和帧带；不能声称仅处理疑点就覆盖全部漏切。第二期也保留连续巡视入口和真实进度。
