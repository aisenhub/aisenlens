# 自动分镜模块计划

## 本阶段范围

以本地视频画面生成可审阅的硬切候选；检测过程可暂停并在同一媒体重新打开后继续，完成结果必须由用户显式应用，不能自动改写现有手动分镜。

## 已确认方案

- 以 96×54 Canvas 的亮度直方图、64 桶色彩直方图和四分区空间特征构成轻量签名，切点以整数 `frame` 保存。
- 首段扫描用当前视频的差分中位数与中位绝对偏差计算自适应阈值；硬切需后续画面稳定确认，渐变转场单独标注。候选附近使用签名缓存二分精修。
- 任务按项目 ID 和媒体指纹持久化扫描游标、参数、候选切点和状态；重新关联不同文件时不会恢复旧任务。
- 任务进行期间持续保存；点击暂停只中断后续采样，已确认的候选结果保留。应用候选时才整体替换当前分镜。

## 参考结论

- OpenReel 的任务桥接将处理与界面进度回调分离，适合作为任务状态边界。
- OpenCut 将媒体时间投影为整数精度，避免将浮点秒值直接作为领域定位数据。
- 旧 AisenLens 的自动分镜实现验证了媒体指纹、分段/游标恢复、低分辨率签名、差分阈值与最小间隔；本项目只吸收这些模式，不复制其实现。

## 修复记录（2026-08-12）

- 页面刷新会终止内存中的 `AbortController`，但此前 IndexedDB 的任务仍标记为 `running`，导致进度卡死且暂停按钮没有可操作的控制器。现在重开项目时会将遗留 `running` 任务转为 `paused` 并持久化；用户可选择继续或使用“重新扫描”清除旧候选后从头开始。
- 修复低检出率：原先仅比较四个区域的平均 RGB，且阈值按不匹配的分数尺度设置，画面平均色相近的硬切会被忽略。现改为亮度直方图、64 桶色彩直方图和四分区空间色彩的复合差分；采样间隔调整为 `0.2` 秒，灵敏度阈值也随新分数尺度校准。
- 将旧项目验证过的候选确认、渐变累积和边界精修迁入独立检测服务，并用当前视频差分分布替代固定经验阈值。候选现在保存 `hard-cut` 或 `gradual-transition` 类型及置信度；仍需显式应用。
- 最短镜头时长的默认值调整为 `0.8s`，可按 `0.1s` 调整至 `0.5s`；低于 `0.5s` 已接近当前 `0.2s` 采样粒度的可靠边界，需先提高采样密度或使用精确解码后再开放。

## 后续优化路线

1. 建立带人工标注切点的本地测试素材集，统计召回率、误报率和边界平均误差；每次算法调整必须对比基准，不凭主观观感宣称更准确。
2. 将签名差分和候选状态机移动至模块 Worker，保留主线程 Canvas 定位；对长视频增加分段扫描、固定重叠与签名缓存的 LRU 上限。
3. 在浏览器支持时引入 WebCodecs 精确解码器，用真实解码时间戳替代 `<video>` seek 的关键帧近似；需维持当前原生 video 路径作为兼容实现。
4. 为素材类型增加可解释的预设与可视化阈值诊断；先输出候选分数与类型，再考虑机器学习模型，不将黑盒结果直接写入分镜。

## 后续边界

- 后续可增加 Worker 计算、渐变转场和边界精修；必须保持候选检测与用户确认应用两阶段分离。
