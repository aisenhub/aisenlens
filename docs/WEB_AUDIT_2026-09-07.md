# AisenLens Web 审核：2026-09-07

## 范围与结论

审核当前工作区的 Web 前端、本地 IndexedDB 仓库、媒体处理、导出、共享场景引擎接入和构建验证配置。排除 Supabase 后端实现，不对桌面端或移动原生端作验收结论。没有修改产品代码，也没有读取或修改用户项目内容来复现破坏性场景。

本次开始时工作区已有 14 个修改文件和未跟踪的 `.agents/`；以下结论包含这些未提交实现，不代表仅针对已提交版本。源文件行号以本次读取版本为准。

产品已有合理的 feature 分层、可复用 UI、页面懒加载、Worker/WASM、本地恢复快照和媒体资源管理基础。优先事项是补齐数据一致性、媒体时序和发布门禁，再处理编辑器状态与长视频性能。无需重写应用或更换技术栈。

## 优先修复的问题

### 1. [P1] 编辑器保存会使用旧项目对象覆盖最新音轨数据

- 位置：`apps/web/src/features/editor/components/EditorWorkspace.tsx:303`（媒体更新入口）、`:733`（saveCurrentProject）、`:786`（整对象更新）；`apps/web/src/features/project/services/projectRepository.ts:369`；`apps/web/src/pages/EditorPage.tsx`；`apps/web/src/app/App.tsx` 的 onProjectLoaded 回调。
- 代码证据：音轨操作更新 `mediaProject` 并写库；编辑器自动保存却展开 `project` 属性。`project` 来自 ProjectMediaGate 的局部状态，onProjectUpdated 只通知 App；App 只保存项目 ID 和标题，没有把完整的新项目对象同步回 Gate。仓库 updateProject 直接 `put` 整个对象。
- 触发：导入或调整音轨后再编辑批注、模板或蒙版，引发自动保存。旧 `project.mediaAssets/audioTracks` 可覆盖刚写入的媒体状态。
- 建议：统一项目状态来源；把保存变成对最新记录的字段更新，并在同一事务内检查版本。音轨与编辑器共用持久化协调入口，避免两个对象各自整包写回。
- 验收：导入音频 → 编辑批注 → 保存 → 重新打开，音轨、素材引用及批注均保留；快速连续调节也不能丢最后一次改动。
- 证据级别：完整代码数据流确认，未在用户项目上执行覆盖复现。

### 2. [P1] 站内离开编辑器可能丢失最近输入

- 位置：`apps/web/src/features/editor/hooks/useEditorSaveState.ts:11,75`；`apps/web/src/features/editor/components/EditorWorkspace.tsx:2605,2692`。
- 代码证据：400 ms 防抖保存；卸载只清除计时器；两个返回项目库按钮直接 `onNavigate(2)`。beforeunload 不能保护 React 站内切页，当前也没有路由离开阻拦。
- 触发：输入后立即返回项目库，或保存失败后离开页面。待保存变更可能随组件卸载消失。
- 建议：显式离开操作先等待保存，保存失败留在编辑器并显示可操作错误；浏览器后退和其它站内导航使用相同离开保护。不要依赖卸载阶段异步写库成功。
- 验收：修改后 100 ms 内离开、保存中离开、写入失败后离开、浏览器后退分别覆盖。

### 3. [P1] 多音轨预览会漏播后来开始的片段，倍速和暂停竞态也未统一

- 位置：`apps/web/src/features/media/hooks/useMultiTrackAudioPreview.ts:75-105`；`apps/web/src/features/editor/components/EditorWorkspace.tsx` 调用 useMultiTrackAudioPreview 处。
- 代码证据：只调度当前时刻已处于区间内的 clip。若音频时钟与视频时间差小于 0.35 秒，则直接返回；正常顺序播放跨越下一个 clip 起点时也返回，没有安排新音源。定向 hook 桩验证已复现。
- 相关风险：接口没有 playbackRate；AudioBufferSourceNode 默认 1 倍速。暂停仅 stopScheduledAudio，没有使正在进行的解码 requestId 失效，解码完成后仍可能启动。音轨静音/增益变化也可能被时间差判断提前跳过。
- 建议：独立播放调度器，明确处理 play/pause/seek/ratechange/轨道变更；提前调度即将进入窗口的片段。暂停、跳转和新请求统一使旧任务失效。
- 验收：从片段起点前开始播放、跨 clip 边界、2 倍速、解码中暂停、播放中静音和删除轨道。

### 4. [P1] 构建通过掩盖了实际类型错误

- 位置：`apps/web/package.json:8`；`apps/web/eslint.config.*`；`apps/web/src/features/editor/components/EditorWorkspace.tsx:2035`。
- 实测错误：App 调用不存在的 `PlatformClient.logout`；平台客户端导入不存在的 SessionExchangeResponse/SessionResponse、传递不存在的 appSlug、调用不存在的 exchangeSession/getSession；编辑器向 PanelToolId 传入 `"video"`，当前合法值已改为 material 等。
- 六项属于前端与平台 SDK 的契约不匹配，本次未审核其后端实现。另一个无效面板值意味着打开旧视频面板的路径不会命中现有工具。
- 建议：对齐实际客户端契约，移除失效调用与面板标识；增加 Web typecheck，将类型检查、lint、核心测试和构建接入统一检查入口及持续集成。逐步恢复 hooks 依赖检查，而不是永久关闭。
- 验收：上述独立编译器检查零错误，故意引入无效面板值或 SDK 方法时发布检查必须失败。

### 5. [P1] 导出与编辑器使用不同的分镜右边界规则

- 位置：`apps/web/src/features/editor/components/EditorWorkspace.tsx:767`；`apps/web/src/features/export/services/videoExport.worker.ts:23`；`apps/web/src/features/export/services/videoExportService.ts:114`；`apps/web/test/video-export-verification.ts:193`。
- 代码证据：编辑器保存 `endFrame = last + 1`，即右端不包含；导出选段使用 `frame <= endFrame`，时长还额外 `+1`。测试导出 fixture 则写入 `durationFrames - 1`，沿用了闭区间，掩盖生产数据的问题。
- 已验证：相邻分镜 `[0,30)` 和 `[30,60)`，第 30 帧实际使用第一段分析文字。
- 建议：所有读写和导出统一为 `[startFrame,endFrame)`；导出匹配 `< endFrame`，时长按差值计算；测试通过真实保存服务生成数据。
- 验收：边界前一帧、边界帧和最后一帧信息正确，导出显示的分镜时长与编辑器一致。

### 6. [P1] 项目卡片缺少键盘打开入口，基础灰字对比度不足

- 位置：`apps/web/src/features/project/components/ProjectLibrary.tsx:170`；`apps/web/src/components/ui/surface-card.tsx:5`；`apps/web/src/index.css:63,111`；`apps/web/src/features/editor/components/ShotList.tsx`。
- 代码及浏览器证据：项目卡片是带 onClick 的 section，无链接、tabIndex 或键盘处理；项目库无障碍树中只有卡片内管理按钮，没有打开项目的语义按钮/链接。
- 对比度计算：深色正文辅助色 `#555555` 对 `#0d0d0d` 为 2.61:1；浅色 `#8a8880` 对 `#edece8` 约 3.00:1。两者都用于普通字号的状态/辅助文字，低于普通文本 4.5:1 要求。禁用控件及纯装饰不计入这一判定。
- 建议：项目标题/主要打开区使用链接或 Button，避免把整张卡片变成包含其它按钮的嵌套按钮；调整 muted token，并按真实叠加背景检查状态色。
- 标准依据：[WCAG 1.4.3](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)、[WCAG 2.1.1](https://www.w3.org/WAI/WCAG21/Understanding/keyboard.html)。
- UI 后续可用 `$impeccable harden`、`$impeccable colorize`。

## 第二优先级：稳定性和性能

### 7. [P2] 自动保存分散在多个事务，快照也不是一致读取

- 位置：`apps/web/src/features/editor/components/EditorWorkspace.tsx:786-800`；`apps/web/src/features/project/services/projectRecoveryService.ts:8`。
- 当前先保存项目，再并行保存分组/批注/模板，最后保存分镜。中途配额不足或事务失败，前面成功部分不会回滚；快照从不同只读事务读取，可能碰到一半新、一半旧的状态。restoreProjectRecoverySnapshot 已使用多 store 事务，可作为同仓库现有范式。
- 建议：提供保存完整编辑快照的单个 IndexedDB 事务，按 revision 判定成功；恢复快照使用一致只读事务。跨标签页编辑增加版本冲突检测或编辑占用机制。
- 验收：中途失败不能留下半套分镜/分组状态；旧标签页不能静默覆盖新数据。

### 8. [P2] 编辑器每帧执行全量序列化及列表计算

- 位置：`apps/web/src/features/editor/hooks/useVideoPlayback.ts:87` 附近；`apps/web/src/features/editor/components/EditorWorkspace.tsx:826`；`apps/web/src/features/editor/components/ShotList.tsx:44,71`。
- 当前 requestVideoFrameCallback 每帧更新父级 React state；父级每次 render 都 JSON.stringify 全部镜头、批注、模板与蒙版。ShotList 每次构造分组 Map、执行过滤并遍历全部镜头渲染。不是只有改文档时才执行。
- 另有撤销：每次提交 structuredClone 多组全量文档，最多 100 份；不代表小项目必然卡顿，但数据规模增长时成本确定增加。
- 建议：播放时钟只驱动时间码/播放头/预览；文档改动通过显式 revision 标脏；文档状态使用 feature 内 Zustand store 和选择器；大镜头列表按可视区渲染；历史采用结构共享、命令或差量，先量化再调整。
- 验收建议：100/1,000/5,000 镜头的播放、打字、滚动和撤销基准；确认播放器更新不再使不相关列表整树更新。
- UI 性能后续可用 `$impeccable optimize`。

### 9. [P2] 长视频波形与混音仍全量驻留内存，取消不能及时终止准备阶段

- 位置：`apps/web/src/features/video/services/waveformService.ts:57`；`apps/web/src/features/export/services/videoExportService.ts:129-185`；`apps/web/src/features/media/hooks/useMultiTrackAudioPreview.ts:45`。
- 波形 fetch 整视频 arrayBuffer，再 slice 复制，再整段 decodeAudioData，随后主线程扫描所有采样。requestIdleCallback 只是延迟开始，不会使后续扫描自动分片。
- 导出完整解码音频、全时长 OfflineAudioContext 混音，再复制声道数组。仅 1 小时、48 kHz、双声道 float32 PCM 就约 1.29 GiB；这只是原始样本大小算术估算，不含源文件、混音输出或其它副本，不是峰值实测。
- prepareAudio 没有取消信号；cancel 要等它完成后才被下一次 cancelled 检查发现。预览 AudioBuffer 缓存也没有预算/淘汰。
- 建议：沿现有媒体管线分段解码和波形采样；块式混音与编码、预算与缓存淘汰；AbortSignal 贯穿准备流程。浏览器不支持的能力应有明确提示。
- 验收：至少短片、长片、多音轨三档内存测量，并记录点击取消到资源释放的时间。

### 10. [P2] IndexedDB 连接异常与升级缺少恢复处理

- 位置：`apps/web/src/features/project/services/projectRepository.ts:115` 的 openDatabase。
- 当前缓存 databasePromise；失败后不清空。没有处理 onblocked、连接 onversionchange 或异常 close。旧标签页持有旧数据库连接时，新版本升级可一直等待，UI 又没有说明。
- 建议：失败/关闭后清空缓存；versionchange 主动关旧连接并提示刷新；blocked 给出关闭其它标签页的明确行动提示。本地存储容量提示、备份和缓存清理已经存在，可沿其扩展。
- 依据：[MDN IndexedDB 使用指南](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)。

### 11. [P2] 路由没有错误边界，部分编辑器读取没有错误及过期请求处理

- 位置：`apps/web/src/app/AppPages.tsx:70` 附近；`apps/web/src/main.tsx`；`apps/web/src/features/editor/components/EditorWorkspace.tsx:880-1045`。
- 页面有 lazy + Suspense，但整个 src 未找到 ErrorBoundary 或路由 errorElement。资源加载失败、模块导出错误、组件 render 异常没有应用恢复 UI。Suspense 的加载提示不是失败处理。
- 部分 shots/markers/groups/template 的异步读取没有 catch，也没有像 ProjectMediaGate 那样的 requestId/active 保护；快速切换或加载失败时可能留在不完整状态。
- 建议：应用/编辑器边界提供重试与返回项目库；异步读取显式 error state、忽略过期结果。保存错误保留错误原因，而不只改变图标。
- 依据：[React lazy](https://react.dev/reference/react/lazy) 明确由最近 Error Boundary 处理加载 Promise 的拒绝。
- 后续可用 `$impeccable harden`。

### 12. [P2] 干净构建依赖工作区外的相邻仓库

- 验收：只有声明依赖的干净 checkout 能完成 Web typecheck、build 和公开页面预渲染。本次没有执行远程部署。

### 13. [P2] 编辑器固定多栏布局缺少窄屏收纳

## 后续架构整理与非阻断优化

- **拆分应解决职责问题。** EditorWorkspace 约 3,692 行，业务命令、持久化、历史、媒体/导出任务、快捷键和 JSX 集中。先解决单一文档状态与保存协调，再提取 controller/hook 和面板。App 约 280 行仍含会话/用户资料流程；页面包装和 feature 目录已经存在，不能说架构迁移完全没做。
- **包体按入口分析。** 本次最大 JS chunk 641.68 kB（构建输出的未 gzip 大小），CSS 118.04 kB；不能把所有 Worker/懒加载 chunk 相加称首页下载量。优先确认主入口依赖图，再将导出对话框/标定工作台等低频能力按需加载。
- **字体本地化。** index.css 第 1 行通过 Google Fonts @import 请求字体，离线/弱网会受影响；项目已声明 Geist 包但当前主字体并非 Geist。保持现有字体设计时可交付所需字体子集，不必因 detector 的审美提示换字体。
- **备份包加强校验。** projectBackupService 的 validate 仅校验部分顶层字段，随后直接遍历 mediaAssets/audioTracks/shot.screenshotIds 等；ZIP 读入未核对 CRC。导入应在写库前完成结构、引用、大小和资源完整性验证，并确保所有写入步骤受失败清理保护。当前已有部分回滚，不应描述为完全没有回滚。压缩包自实现与 xlsx 导出中类似工具逻辑可在实际需要时整理，不能仅为减少行数引入新依赖。
