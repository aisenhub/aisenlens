# 分镜截图与画面采样模块拆分计划

## S1 本地截图资源（已完成）

- [x] 通过原生视频帧与 Canvas `toBlob()` 生成 JPEG 截图，图片只写入本地 IndexedDB。
- [x] 每张截图保存稳定 ID、所属项目、帧号、分辨率、格式、大小与采集时间。
- [x] 截图二进制与结构化分镜数据分仓存储。

## S2 分镜截图关系（已完成）

- [x] 分镜保存 `screenshotIds` 与显式 `primaryScreenshotId`；它是后续表格导出的唯一代表图引用。
- [x] 默认自动采集分镜首帧并设为代表图；边界变化时仅当它仍为默认图才跟随更新。
- [x] 用户采集当前帧会直接替换代表图；手动指定后不再随首帧变化而覆盖。
- [x] 分镜截图不再自动改写项目封面，项目封面与分镜主截图是两类独立引用。

## S3 编辑器交互（已完成）

- [x] 编辑器右侧“画面”面板提供分镜截图画廊、截图数量、帧号、主图标识与采集操作。
- [x] 缩略图使用当前浏览器临时 Object URL 展示，不额外持久化第二份缩略图资源。

## 规则

1. 完整 JPEG 是唯一正式截图资源；缩略图是可随时重新生成的展示层资源。
2. 分镜截图仅属于一个分镜；分镜拆分后的新镜头不继承原镜头截图。
3. 主截图是显式引用，不依赖截图数组的位置；未手动指定时由首帧引用填充。
4. 用户更新代表图时，旧的用户代表截图会同时删除其本地元数据与二进制资源。
