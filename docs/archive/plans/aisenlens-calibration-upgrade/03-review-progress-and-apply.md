# C3 — 巡视进度、待回看、应用事务与回流

前置：C1 契约与 C2 真实播放/帧定位已接入。读取 00-master-plan.md，不复活旧的仅 excludedCandidateIds 产品路径。

## 1. 两种进度，不合并成准确率

1. **已播放巡视范围**：仅校准页面可见、视频真实前进且非 seek/buffering/后台时，累计播放经过的时间范围。文案不写“已确认无漏切”。
2. **已复核范围**：用户明确选择“此段已检查”形成的范围。可用于观看中断后恢复，也支持用户检查帧带后主动确认。

顶部显示“已巡视 XX:XX / 总时长 · 已复核 XX:XX · 待回看 N”，总量按范围并集计算，不把重复循环相加。空间不足时保留一个主进度，其他在详情中显示。

播放覆盖计算：保存连续观测段；暂停、seeking、waiting、error、visibilitychange 隐藏和页面离开时关闭段；恢复后新建段。若媒体时间跳变与墙钟、倍速明显不符，视为不连续，不填补中间空白。任何 seek/fastSeek、程序定位、拖播放头都不能一次涂满被跨越区间。后台播放不新增巡视。

requestVideoFrameCallback/mediaTime 是信号之一，不能推导用户看到了每个帧。只持久化合并后的有界范围，不为每次帧回调写DB或 append 记录。局部循环只计一次；倍速播放显示真实速度，不自动升级为“明确复核”。

草稿结构修改后：已播放范围仍成立；受影响的明确复核范围失效并标待复核，待回看项不能因重编号消失。补切/移点以被影响的原左右区段为失效范围，避免简单清空全片进度。算法重新检测不增加人工巡视进度。

建议 `services/reviewCoverageService.ts` 放纯区间逻辑，`hooks/useCalibrationCoverage.ts` 只采集事件并派发，进度不混入播放器底层时钟。

## 2. 待回看清单

导航提供“镜头”和“待回看”，不在第一期显示不存在的智能疑点页签。默认按媒体时间排序。

- 当前帧一键标记，备注可选，重复位置提示已有待回看，不连续生成重复项。
- 点击定位但不自动完成；明确“标记已处理”或用户选择完成动作后才更新。
- 问题处理完成可去下一项；始终可返回原巡视位置。
- 补切不是所有待回看的必然解决：转场不确定/画面判断备注仍需用户处理。
- 已处理可筛选查看和重新打开；均保留稳定 id/媒体帧位置。
- 待回看属于产品校准草稿，不能混入研究 Annotation 或创作 Marker 列表。

## 3. 完成与应用界面

“完成并应用”打开真实变更摘要：新增切点、移动切点、删除切点、最终镜头数、受影响的既有内容，以及未巡视范围/未处理待回看数。统计通过基线与当前草稿差异得出，undo 到基线则相应归零。

未巡视或有待回看时允许明确选择“部分复核并应用”，保存真实状态；不能自动宣称校准完成。全部巡视也不宣称机器已保证零漏切。无结构变化时可保存复核状态并继续，不重建正式镜头、不制造快照和版本变动。

页面 Apply/Confirm 期间互斥且显示进度，重复点击不会生成两次应用。媒体不匹配、project/task/draft版本变化、保存/快照失败则停止，保持草稿可恢复，展示可执行的重新加载或重试动作。

## 4. 正式内容保留规则（不能只改边界数组）

校准可以进入已有分析的项目，采用稳定身份与明确 lineage，不用“范围变了就生成全新镜头并丢掉原数据”。实际输入输出复用 ProjectEditorState/StoredShotRecord 序列化。

| 操作 | 正式内容处理 |
| --- | --- |
| 未变区段 | 保留 shot ID、笔记、分析、截图及来源 |
| 移动已有边界 | 左右 shot ID 不变；笔记/分析保留并提示边界已改需复核；仅受影响首尾自动截图失效重建；不删手工截图 |
| 补切 | 左镜 ID 保留，右镜新 ID；原笔记/分析保留在左镜并提示内容原覆盖更长范围，右镜为未分析；不把原分析复制为新镜头的已确认分析 |
| 删除边界/合并 | 保留左镜 ID；保留双方原笔记及分析内容，带源镜头标识，字段冲突进入明确复核数据/界面，禁止默默以左覆盖右 |
| 手动截图与主图 | 截图本体与用户内容永不因校准静默删除；有可靠帧位置则重关联对应新镜头；位置未知则保留原关联并提示核对，不假设帧位置 |
| 自动首尾截图 | 按新的实际边界失效和重建索引，旧 Blob 仍受恢复快照引用保护 |
| Marker | 保留媒体位置、类别、标签、备注；shotId 仍有效则保留，失效则按可确定位置关联或置 null，不能删除用户 Marker |
| Group | 补切在原位置插入右镜；合并替换原 ID 并去重；复用 reconcile 检查连续性/最少两镜等规则；失效分组的变更必须进入应用摘要与快照 |
| 来源 | 保存候选/正式 lineage 与人工修改事实；不能仅靠原范围精确匹配找 candidate，否则移动/合并会丢来源 |

C1→C3 交接必须定义复杂分析字段合并的实际类型及展示入口。建议保留原分析为带 sourceShotId 的复核附件，当前单值冲突字段标未确认，不能将冲突值转成无结构字符串冒充原字段。优先复用已有笔记/分析承载能力；若确需扩展类型，应同步序列化、导出与 tests，不增加旧 schema 兼容层。该点不得留给 UI agent 随意选择。

模板、媒体关联、多音轨、overlay、无关 markers 和用户设置保持完整；不得用一个仅含 shots 的保存对象覆盖整个项目。

## 5. 原子应用（强制顺序）

当前代码的“先写 task，再 setShots 并等 autosave”必须替换。服务编排位于 `features/shot-calibration/services/calibrationApplyService.ts`；实际事务位于现有 projectRepository。

1. 获取项目写锁，阻止草稿修改/重复 apply 与竞争 autosave；跨标签页依靠仓储版本校验，不能仅依赖按钮 disabled。
2. flush 最新正式编辑与草稿保存；任何失败停止。取得已落盘 expectedProjectVersion、draftRevision、可选 taskVersion 与媒体身份。
3. 基于最新草稿生成应用计划。预览 token 包含 draft/project/task/media 版本；有变化则要求刷新预览。不要使用 Dialog 打开时缓存的旧 output。
4. 创建应用前恢复快照，必须包含 flush 后最新的笔记等正式内容。快照失败停止。
5. 在一个 readwrite transaction 内读取并再次校验全部 expected version 和媒体身份。写入完整正式文档（shots/groups/markers/分析/引用）、草稿应用回执、必要 task appliedAt/复核状态。仓储方法可命名 `applyCalibrationDraft`，不得假装旧方法已存在。
6. 任一写失败 abort，正式文档、task、草稿 applied 状态全部不变。快照可保留；失败不删除已有可靠恢复点。
7. 只有 tx.oncomplete 后才同步内存正式状态、autosave 基线、task controller 与 history，避免陈旧 autosave 或任务保存随后覆盖提交。
8. 成功只记一次正式历史变更，清理 obsolete 草稿编辑栈并保存已应用回执；解锁后进入 Overview。存在未处理项则在概览显示部分复核，不伪造全片确认。

事务内不做网络/解码/快照压缩等会令 IDB transaction 失活的异步工作；所有计算和快照在事务外准备，事务内做版本复验与DB操作。

幂等键建议 draftId + revision。若数据库已提交但UI尚未同步时崩溃，重进按回执重建正式状态，不能再次应用并重建ID。应用原正式镜头草稿时不强制依赖可选检测 task；有来源记录不等于必须重写历史 task 原始结果。

## 6. Undo、重新进入和冲突

应用前：草稿 history。应用后：既有正式 editor history，一次 undo 恢复整个应用前状态与关联内容；确保 undo 结果会持久化。task.appliedAt 是历史事实，不用它证明当前结构仍已校准。

正式 undo/redo/Analyze 手改/恢复快照之后，当前校准结果标记必须通过正式版本验证，过期草稿不得自动复用。重新进入优先当前未冲突草稿，否则以当前正式镜头为基线；没有有效草稿才考虑新检测结果。已应用但无待回看的草稿可作为 receipt 保存，不变成另一套可编辑正式文档。

重新扫描覆盖草稿和采用新检测输出属于有损替换，需要产品内明确变更预览，不自动执行。无需每次补切、移点都弹确认。

## 7. 验收与故障注入

- 最新笔记刚输入立刻 Apply，快照和正式内容都包含该笔记。
- 分别让 flush、snapshot、task write、shots write、groups write、draft receipt write 失败，重载后不出现半应用。
- 预览打开后修改草稿、正式文档、task 或媒体，旧预览不可提交。
- 应用中双击、双标签页竞争、完成后页面崩溃，再打开只出现一次有效应用。
- 补切/移点/合并后全部关联内容按表保留，完整备份与恢复能通过引用校验。
- 播放10秒与跨越seek到60秒区分；缓冲、后台、重复循环、2×播放均不伪造确认。
- 标记待回看后补切、合并和刷新，该项仍定位同一媒体位置。
- Analyze修改后重进校准看到最新结构，研究真值未被改变。
