# 视频加载与解码能力优化计划

## 目标

在不改变“本地文件引用、原生视频交互预览、Mediabunny 离线处理”边界的前提下，让 AisenLens 能清楚、稳定地处理不同容器、编码、帧率和浏览器能力组合：

- 用户能够知道视频是不可读取、可预览、可精确取帧，还是仅缺少某一项能力。
- 打开项目时优先让预览可用；元数据补全、缩略图和波形不能阻塞播放。
- 截图、帧带、代表图、自动分镜和导出复用有限内存的离线解码会话，不重复读取同一媒体。
- 可变帧率视频以真实呈现时间戳为准，不把平均帧率误认为精确帧边界。

## 已确认边界

| 职责 | 固定方案 | 不采用的方案 |
| --- | --- | --- |
| 文件来源 | `FileSystemFileHandle` + 指纹；录音等自有 Blob 素材单独存储 | 复制用户原始视频到 IndexedDB、上传到服务器 |
| 交互预览 | 原生 `HTMLVideoElement`、媒体事件与 `requestVideoFrameCallback` | 用离线 Canvas 解码替换正常播放 |
| 容器与轨道解析 | Mediabunny `Input` / `BlobSource` | 只信任扩展名、MIME 或 `canPlayType()` |
| 精确帧处理 | Mediabunny `CanvasSink` 和真实帧时间戳 | 用原生 `seeked` 作为截图/分析的静默替代 |
| 资源管理 | 按素材 ID 复用、有限缓存、显式释放 | 全局永久缓存、每次请求重新创建解码器 |

原生预览成功并不代表离线精确解码成功；反之，容器可解析也不代表当前浏览器可播放。三个结论必须独立保存和展示。

## 能力模型

### 1. 素材访问状态

```text
unlinked
  -> needs-permission
  -> opening-file
  -> fingerprint-mismatch | missing | accessible
```

- `needs-permission` 只能显示用户主动授权按钮，不能在页面加载时弹出权限请求。
- 每次从句柄取得 `File` 后都检查指纹；不匹配视为缺失，不允许替换原项目的源视频。
- `accessible` 只说明文件可以读取，不说明可播放或可解码。

### 2. 媒体能力矩阵

每个视频素材维护一次探测结果，使用独立字段而非单一 `supported` 布尔值：

| 能力 | 获取方式 | 成功含义 | 失败后的产品行为 |
| --- | --- | --- | --- |
| 容器可解析 | `Input`、主视频轨、时长与轨道查询 | 可读取轨道、尺寸、旋转、编码、音频轨信息 | 阻止进入编辑器，提示文件损坏或容器不支持 |
| 原生预览 | `<video>` 的 `loadedmetadata`、`canplay`、`error` | 当前浏览器可实际交互播放 | 显示无法预览；不假装可以播放 |
| 离线视频解码 | `videoTrack.canDecode()` | 可生成精确截图、帧带、自动分镜和导出画面 | 仍可在原生预览成功时观看，但禁用精确帧能力并说明原因 |
| 离线音频解码 | `audioTrack.canDecode()` | 可生成波形、混音和带声音导出 | 保留无音频预览，禁用或降级相关音频任务 |
| 时间轴精度 | 包统计、帧时间戳分布 | 可识别恒定帧率或可变帧率 | 可变帧率按时间戳定位，不使用虚构的帧号精度 |

探测结果包含机器可读的失败分类（权限、容器、原生预览、视频解码、音频解码、未知），UI 再映射为用户可理解的文本。不要把浏览器原始错误直接展示给用户。

## 目标架构

### 媒体资源层

新增或整理以下职责，业务组件不直接访问文件句柄、对象 URL 或 IndexedDB：

| 服务 | 职责 | 主要消费者 |
| --- | --- | --- |
| `features/media/services/mediaAssetResourceService.ts` | 权限只读检查、按素材 ID 取得当前 `File`、指纹校验 | 项目打开、预览、离线服务 |
| `features/media/services/mediaProbeService.ts` | 动态加载 Mediabunny，解析容器、轨道、编码、旋转、包统计和离线能力 | 导入、元数据补齐、兼容性面板 |
| `features/media/services/mediaPreviewResourceService.ts` | 为一个活跃预览维护一个对象 URL，切换/卸载时释放 | `ProjectMediaGate`、编辑器预览 |
| `features/video/services/videoDecodeSessionService.ts` | 按素材 ID + 指纹管理 `Input`、`CanvasSink`、顺序迭代器和小型帧缓存 | 帧带、截图、代表图、自动分镜、导出前取帧 |

`ProjectMediaGate` 只负责协调加载状态和用户授权；编辑器只接收预览 URL、媒体信息和能力状态。离线处理服务一律通过素材 ID 取得文件，禁止接受对象 URL 后再 `fetch()` 为 Blob。

### 解码会话生命周期

```text
acquire(assetId, fingerprint)
  -> get File
  -> create Input + CanvasSink
  -> sequential request: current frame + one-frame lookahead
  -> reuse while fingerprint unchanged
  -> cancel stale seek / release iterator
  -> dispose on project change, fingerprint change, memory pressure, explicit clear
```

- 每个会话把定位请求串行化；新的快速拖动请求会使未开始的旧请求失效。
- 只保留当前帧、下一帧以及受字节上限约束的少量缩略帧。缓存淘汰时关闭 `ImageBitmap`、归零临时画布或释放引用。
- 连续向前播放使用迭代器推进；反向、跳跃或跨越预取窗口时重建迭代器，不在后台无限解码。
- `Input.dispose()`、迭代器 `return()` 和对象 URL `revokeObjectURL()` 必须由会话所有者调用一次且仅一次。

### 元数据与时间映射

- 读取显示尺寸、旋转、时长、视频/音频编码、音轨数量、声道数、采样率、平均包率与码率。
- 继续保留当前 `frameRate` 作为编辑器网格和快捷键的工作帧率；新增“帧率模式”或等价诊断，区分恒定帧率、可变帧率和未知。
- 可变帧率素材的分镜边界和截图以秒为权威值，显示帧号仅是由工作帧率推导的编辑标签；最终截图/导出取最近真实呈现帧。
- 不能在没有实际帧索引的情况下承诺逐帧无误差。需要精确帧编号的后续功能必须单独建立时间戳索引和持久化策略。

## 分阶段实施

### P0：基线与测试夹具

**工作**

1. 为当前导入、授权、预览、截图、帧带和导出链路补充日志边界与可观测状态，不改变用户交互。
2. 建立可生成或可本地选择的测试矩阵：H.264 MP4、VP9/AV1 WebM、ProRes/HEVC MOV、MKV、无音频、双音轨、可变帧率、损坏文件、权限被撤销文件。
3. 编写浏览器测试，覆盖对象 URL 释放、权限不自动请求、解析失败不写入项目、预览失败不污染已有项目。

**验收**

- 每个失败都归入一个稳定错误类别。
- 旧项目在不重新选择视频的情况下保持可打开和可重新关联。

### P1：探测服务与能力持久化

**工作**

1. 从 `project/services/mediaService.ts` 中抽离容器探测到 `mediaProbeService`，选择文件服务仅保留选取、指纹和句柄操作。
2. 先执行轻量容器探测，再异步运行较贵的包统计；预览 URL 创建与 `<video>` 加载并行，不等待缩略图、波形或包统计。
3. 扩展 `MediaAssetMetadata` 或同等的诊断结构，保存编码、旋转、能力矩阵、探测时间与失败类别；删除已废弃的模糊状态字段。
4. 已有关联项目只在缺失字段时后台补齐，补齐失败不覆盖原有可用元数据。

**验收**

- 导入完成后可以区分“容器可读但浏览器不能播放”和“可播放但不能精确取帧”。
- MIME 为空或扩展名不常见时，只要容器实际可解析就能给出正确结果。

### P2：项目打开与预览资源生命周期

**工作**

1. 将 `ProjectMediaGate` 改为消费访问状态、探测状态和预览状态，不直接构造或释放对象 URL。
2. 创建 `mediaPreviewResourceService`，保证同一活跃预览仅存在一个 URL，并在素材切换、项目退出、重新关联和错误恢复时释放。
3. 用 `loadedmetadata` 更新展示信息，用 `canplay` 标记可交互预览，用 `error` 更新预览能力；不将 `loadedmetadata` 当作可播放证据。
4. 权限恢复、重新关联和重试均复用同一状态机，避免并发打开项目写入过期状态。

**验收**

- 快速切换项目不会出现旧视频闪现、过期错误或对象 URL 累积。
- 预览失败时，项目数据保留，用户可以重新授权或重新关联。

### P3：共享离线解码会话

**工作**

1. 实现 `videoDecodeSessionService`：一个素材对应一个 `Input`、`CanvasSink`、串行请求队列、当前帧/下一帧预取和显式 `dispose`。
2. 迁移 `frameThumbnailService`：不再 `fetch(sourceUrl)`，改为按素材 ID 从资源层取得文件并复用会话。
3. 依次迁移分镜首尾帧、代表图、帧带和自动分镜；每次迁移后删除旧的重复解码入口，而非保留双轨路径。
4. 导出 Worker 仍独立拥有自己的输入与生命周期，不能与主线程预览会话共享可变解码对象。

**验收**

- 连续帧请求只初始化一次容器输入；跳跃定位可取消旧请求。
- 项目关闭后无残留解码会话、迭代器或活动对象 URL。
- 截图与帧带对同一时间点得到一致画面。

### P4：可变帧率与精度策略

**工作**

1. 用真实帧时间戳验证当前工作帧率映射误差，定义何时标记为可变帧率或未知。
2. 将截图、分镜边界和导出图层的时间输入统一为秒；UI 帧号只作为编辑辅助值。
3. 评估是否需要为长视频建立稀疏时间戳索引；只有发现实际产品需求后才新增持久化索引，避免导入阶段扫描全部视频。

**验收**

- 可变帧率素材拖动、截图和分镜导出不会因为平均帧率累计漂移。
- 恒定帧率素材的现有快捷键和时间轴行为保持不变。

### P5：兼容性反馈与体验完善

**工作**

1. 在视频信息位置以紧凑状态显示“可预览 / 可精确取帧 / 含音频”的能力，不增加重复设置面板。
2. 需要离线能力的按钮根据能力矩阵禁用，并给出具体原因和可行操作。
3. 探测中的预览优先可用；后台任务通过低干扰进度反馈，不阻塞编辑器进入。
4. 记录解码会话初始化耗时、定位耗时、缓存命中率和峰值缓存字节数，作为后续优化依据。

**验收**

- 用户无需理解容器与编码细节，也能知道可执行哪些工作。
- 不存在“点截图后才发现格式不支持”的延迟失败。

## 验证清单

| 场景 | 必测结果 |
| --- | --- |
| 首次导入正常 MP4 | 预览快速就绪；随后补全容器、编码和解码能力 |
| 原生可播、离线不可解码 | 可播放；精确帧功能明确禁用；项目可保存 |
| 容器可读、原生不可播 | 不进入假就绪状态；显示浏览器预览不支持 |
| 句柄权限撤销 | 不自动弹窗；用户点击授权后恢复或清晰失败 |
| 同一项目连续截图/帧带 | 复用一个解码会话；释放后无残留资源 |
| 快速拖动或切换项目 | 旧请求不覆盖新状态；旧会话被释放 |
| 可变帧率素材 | 截图时间稳定；不宣称平均帧率提供精确帧号 |
| 损坏或伪装扩展名文件 | 不创建可用媒体资产；错误信息可操作 |

## 性能门槛

- 正常素材的预览 URL 创建与原生加载不得等待缩略图、波形或完整包统计。
- 同一素材连续离线取帧不重复创建 `Input`；解码缓存必须有帧数和字节双重上限。
- 任意素材切换、项目离开、重新关联或异常后，缓存和对象 URL 均可被释放。
- 压力测试以相同素材记录首次探测耗时、连续定位耗时、缓存命中率、峰值缓存字节和项目切换后的资源数量。

## 风险与处理原则

- 浏览器支持依赖容器、编码、硬件与版本组合，能力探测结果只对当前浏览器和当前文件有效，不写死格式白名单作为最终判断。
- File System Access API 是优先的本地引用方式；没有该 API 时仅支持当次选择的临时预览，不伪造可跨刷新恢复的本地关联。
- 不以原生视频定位替代需要精确性的离线解码；这会在关键帧、长 GOP 和可变帧率视频中产生不可见但真实的误差。
- 本计划不改造导出音频分段、字幕或多轨剪辑能力；它们继续按 `VIDEO_MEDIA_PIPELINE_PLAN.md` 的独立计划推进。
