# AisenLens 素材准备工作台 UX / UI 设计方案

> 术语说明：正式产品语言统一使用“素材准备”；“前处理”仅在原始章节/工程语境中保留。
> 文档定位：AisenLens 全局三阶段工作台中「素材准备」Workspace 的产品与交互设计规范  
> 适用范围：素材导入、智能切分、镜头复核、完成素材准备，以及与「逐镜分析」的工作流衔接  
> 上位架构：`素材准备 → 逐镜分析 → 成果应用`  
> 目标读者：产品、设计、前端、架构、算法工程师

---

## 1. 背景与目标

当前 AisenLens 在项目进入后的前处理阶段，已经具备较完整的底层能力：素材关联、自动分镜、参数控制、扫描任务、候选结果、逐帧校准、边界双帧证据、时间线、问题标记、Undo / Redo、草稿保存等。

现阶段主要问题不是“能力不够”，而是**系统能力直接暴露给用户过多，而用户任务流暴露得不够清晰**。

用户真正要完成的任务只有一条：

> **导入视频 → 自动识别镜头 → 复核切点 → 进入逐镜分析**

因此，本次设计的核心目标是：

1. 将“准备”和“校准”从两个独立产品阶段，合并为一个连续的“素材准备”任务。
2. 让页面根据任务状态自动变化，而不是把所有功能模块同时平铺展示。
3. 默认隐藏算法参数、技术指标和工程信息，仅在需要时渐进披露。
4. 把“校准器”从编辑器导向，重构为审核器 / 复核器导向。
5. 让用户感知到自动化价值：系统先完成大部分工作，用户只处理少量不确定项。

核心产品原则：

> **系统复杂，操作简单；分析专业，但用户不需要先成为软件专家。**

---

## 2. 现状问题总结

### 2.1 前处理需要重新对齐新的全局三阶段架构

AisenLens 的全局一级工作区已收敛为：

- 素材准备
- 逐镜分析
- 成果应用

其中：

- **素材准备**：负责把原始视频转换成可靠、可分析的镜头结构；
- **逐镜分析**：负责围绕镜头产生结构化分析数据；
- **成果应用**：负责查看、导出、分享和进一步转化分析成果。

因此，前处理不能继续沿用旧的“准备 / 校准 / 总览 / 深拆 / 学习 / 创作”导航模型。

“校准”应完全并入素材准备内部，成为“镜头复核”步骤；素材准备完成后的唯一主去向是：

> **逐镜分析**

### 2.2 准备页模块并列，而不是任务连续

当前准备页同时包含：

- 素材状态
- 分析模板入口 / 研究配置（旧设计残留）
- 自动分镜参数
- 自动分镜执行
- 扫描结果入口

虽然功能已经合并在一个页面，但用户看到的仍是多个模块，而不是一条连续流程。

### 2.3 主操作竞争

前处理未完成时，如果页面出现“进入逐镜分析”等跨阶段入口，并与“开始智能切分 / 复核镜头”同时争夺主操作权，用户会难以判断当前应完成哪一步。

用户无法判断：

> 我现在应该继续准备素材，还是已经可以开始分析？

### 2.4 参数暴露过多

普通用户会看到：

- 内容预设
- 检出程度
- 转场类型
- 最短镜头
- 高级检测参数
- detector
- threshold
- window width
- H / S / L 权重

即使参数是折叠的，“这些参数存在”本身也会增加认知压力。

### 2.5 扫描过程使用 Modal，导致上下文切换

当前自动分镜流程包含：

主页面 → 扫描弹窗 → 候选列表 → 应用 → 校准页

这会把一个持续任务拆成多个临时上下文。

### 2.6 候选结果存在重复确认

扫描完成后先展示候选结果列表，再进入真正的视频 / 边界校准。

但用户无法仅凭：

- candidate id
- frame range
- score

判断切点是否正确。

真正有价值的是：

- 视频上下文
- 切点前一帧
- 切点后一帧

因此候选列表不应成为独立结果页。

# 3. 新的信息架构

## 3.1 素材准备在全局架构中的位置

AisenLens 项目内一级导航固定为：

```text
素材准备
逐镜分析
成果应用
```

三者分别对应：

```text
素材准备
= 数据输入与镜头结构准备

逐镜分析
= 分析数据生产

成果应用
= 分析数据消费、展示、导出与转化
```

素材准备是三大 Workspace 中的第一层。

它的边界非常明确：

> **输入：原始视频**  
> **输出：可靠、可供逐镜分析使用的 Shot / Boundary 数据**

---

## 3.2 素材准备内部结构

“校准”不再作为一级导航，也不再被用户理解成独立模块。

素材准备内部只有三个连续步骤：

```text
素材准备
  ├─ 导入素材
  ├─ 智能切分
  └─ 复核镜头
```

一级导航回答：

> **我现在处在哪个工作阶段？**

素材准备内部 Stepper 回答：

> **这个阶段我做到哪一步？**

---

## 3.3 与逐镜分析的职责边界

素材准备阶段不负责：

- 分析模板设计
- AI 辅助分析设置
- Scene / 场景分析
- 剪辑节奏分析
- 景别 / 构图 / 运镜等分析字段
- 分析数据表格
- 导出与分享
- 创作转化

这些能力分别属于后续的：

```text
逐镜分析
成果应用
```

特别是：

**分析模板与 AI 辅助都不属于素材准备。**

它们属于逐镜分析工作台的 **Analysis Settings**，通过设置 Drawer / Sheet 进入，而不是前处理中的 Card 或流程步骤。

# 4. 前处理状态机

前处理页面不应按照功能组件切换，而应按照用户任务状态切换。

推荐状态机：

```text
未导入
   ↓
已导入，待识别
   ↓
识别中
   ↓
识别完成，待复核
   ↓
复核中
   ↓
素材准备完成
```

建议产品层路由概念：

```text
stage=prepare
step=import
step=detect
step=review
step=done
```

原有 `calibrate` 可在兼容期保留，但逐步重定向到：

```text
stage=prepare&step=review
```

# 5. 页面整体布局

素材准备必须嵌入统一的 AisenLens Project Workspace Shell 中，而不是拥有另一套独立导航。

桌面端建议：

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ ← 项目库   项目名称                                  已保存        ⚙     │
├────────────────┬─────────────────────────────────────────────────────────┤
│                │                                                         │
│ ● 素材准备     │  素材准备                                               │
│                │  将原始视频整理成可供逐镜分析的镜头序列                 │
│   逐镜分析     │                                                         │
│                │  ✓ 导入素材 ───── ● 智能切分 ───── ○ 复核镜头           │
│   成果应用     │                                                         │
│                │  ┌──────────────────────────────────────────────────┐   │
│                │  │                                                  │   │
│                │  │                    主工作区                      │   │
│                │  │                                                  │   │
│                │  └──────────────────────────────────────────────────┘   │
│                │                                                         │
│                │                                      [ 当前主操作 ]     │
│                │                                                         │
│ ⚙ 项目设置     │                                                         │
└────────────────┴─────────────────────────────────────────────────────────┘
```

设计原则：

- 左侧一级导航始终只表达三大工作阶段；
- 页面内部 Stepper 只表达素材准备的内部进度；
- 顶部 Header 只承担项目级信息，如返回项目库、项目名、保存状态和项目设置；
- 当前页面操作全部留在 Workspace 内；
- 同一时刻只保留一个强主 CTA；
- 素材准备完成后，主 CTA 才切换为“开始逐镜分析”。

素材准备不是一次性 Wizard，但首次使用时可以表现出明确的阶段引导；完成后再次进入时，应以长期 Workspace 状态呈现。

# 6. Step 1：导入素材

## 6.1 空状态

首次进入项目时，页面应该极其简单。

```text
                         ┌────────────────────────┐
                         │                        │
                         │          🎬            │
                         │                        │
                         │     添加分析素材       │
                         │                        │
                         │ 拖入视频，或从本地选择 │
                         │                        │
                         │      [ 选择视频 ]      │
                         │                        │
                         │ MP4 / MOV / MKV ...   │
                         └────────────────────────┘

                     🔒 所有处理均在本地完成
```

此阶段不显示：

- 分辨率
- FPS
- 自动分镜设置
- Scene Engine
- 分析模板
- 高级参数

原则：

> **空状态不要提前解释下一阶段。**

用户唯一要做的事情是：

> 选择视频。

---

## 6.2 素材导入后

导入完成后，Dropzone 消失，页面进入待识别状态。

媒体信息从大 Card 降级为轻量摘要：

```text
霸王别姬.mp4
02:51:22 · 1920×1080 · 24 fps                        更换素材
```

正常状态下：

- 文件名
- 时长
- 分辨率
- FPS

只作为辅助信息。

异常时才提升状态权重。

例如媒体丢失：

```text
⚠ 无法访问原始视频

项目中的分析数据仍然保留，
请重新关联原视频继续工作。

[ 重新关联视频 ]
```

原则：

> **正常状态安静，异常状态突出。**

## 8.1 参数命名原则

算法参数必须转换为用户意图语言。

推荐：

- 保守：减少误切
- 均衡：推荐
- 细致：提高召回

避免默认暴露：

- adaptive threshold
- hard cut detector
- window width
- content score
- hue / saturation / luma weights

原则：

> **产品负责把用户意图翻译成算法参数，而不是要求用户理解算法参数。**

---

## 8.2 “高级参数”改为“专家设置”

不要在主 UI 出现：

> 启用高级检测参数

建议变为：

```text
▸ 专家设置
```

打开后再提示：

```text
专家设置

仅在需要调试自动切分结果时使用。
```

内部可继续保留：

- detector
- threshold
- window
- minimum content difference
- fade threshold
- H / S / L 权重

# 9. 分析模板与 AI 辅助必须彻底离开前处理

前处理只回答：

> **视频应该如何被整理成可分析的镜头？**

逐镜分析才回答：

> **每个镜头应该分析什么，以及 AI 如何参与分析？**

因此，素材准备页面不应出现：

- 分析模板 Card
- 分析模板选择
- AI 辅助分析设置
- AI 分析字段
- 模型 / Prompt 等分析配置

推荐职责关系：

```text
切分策略
↓
属于素材准备
↓
决定视频如何形成镜头


分析模板
↓
属于逐镜分析的 Analysis Settings
↓
决定每个镜头记录哪些分析字段


AI 辅助
↓
属于逐镜分析的 Analysis Settings
↓
决定 AI 如何参与分析字段的生成与确认
```

在新的全局 UI 中，用户进入“逐镜分析”后仍然只看到一个分析工作台。

分析模板和 AI 辅助通过：

```text
模板：电影语言 ▾
✦ AI 建议
⚙ 分析设置
```

等入口进入设置 Drawer，而不是作为素材准备中的页面或卡片出现。

# 10. 识别进行中

扫描过程不应使用 Modal。

页面原地进入“识别中”状态。

### 有真实进度时

```text
正在识别镜头

████████████████████░░░░░░░░      68%

01:46:08 / 02:35:42

已发现 126 个镜头

系统正在分析画面切换。
你可以继续播放视频，也可以离开这个页面。

                                           暂停
```

### 无法精确计算进度时

不要制造假百分比：

```text
正在识别镜头…

◌ 正在分析 01:46:08 附近的画面

已发现 126 个候选镜头
```

---

## 10.1 运行期间设置锁定

扫描任务开始后：

- 参数锁定；
- 设置入口变为“查看设置”；
- 不允许修改影响当前任务结果的参数。

UI 可显示：

```text
切分策略：电影

扫描进行中，参数已锁定
```

避免用户思考：

> 当前任务到底使用旧参数还是新参数？

# 11. 识别完成

扫描完成后，不展示工程化候选列表。

避免默认显示：

- Candidate 01
- hard-cut
- frame 705–942
- score 0.873

改为：

```text
✓ 镜头识别完成

检测到 138 个镜头

系统已经生成初始镜头序列。
建议在进入分析前快速检查切点。

[ 复核镜头 ]


重新识别            查看检测信息
```

主 CTA 只有：

> 复核镜头

---

# 12. 未来目标：只让用户检查不确定切点

理想体验不是：

> 自动切 138 个 → 用户检查 138 个

而是：

```text
✓ 自动切分完成

138 个镜头

129 个切点置信度较高
9 个切点建议确认

[ 检查 9 个切点 ]
```

用户感知会从：

> 机器帮我生成了一堆结果让我审核

转变为：

> 系统已经完成绝大多数工作，只让我处理不确定项

这是前处理体验最重要的长期方向之一。

---

# 13. Step 3：复核镜头

## 13.1 重新定义 Calibration Workspace

Calibration 不再是：

> 镜头编辑器

而是：

> **切点复核器**

核心用户循环：

```text
看
↓
判断
↓
必要时修正
↓
下一个
```

默认路径：

```text
系统定位一个切点
        ↓
查看前后帧 / 视频
        ↓
切点正确？
        ↓
正确 → 确认 → 下一个
错误 → 微调 / 删除 → 确认 → 下一个
```

三栏职责：

| 区域 | 目标 |
|---|---|
| 左栏 | 我现在检查哪个切点？ |

# 16. 左侧复核队列

## 16.1 默认不是“全部镜头”

默认应进入：

> 待确认

而不是：

> 全部镜头

推荐：

```text
复核

  镜头 12 → 13
  淡入淡出

● 00:24:17
  镜头 27 → 28
  快速变化

● 00:51:02
  镜头 43 → 44
  黑场
```

长期目标可增加：

```text
[ 待确认 ] [ 全部 ] [ 已处理 ] [ 稍后处理 ]
```

---

## 16.2 导航实体从 Segment 转为 Boundary

复核任务真正判断的是：

> 镜头 27 与镜头 28 之间的切点是否正确？

因此产品层导航实体应该是 Boundary，而不是 Segment。

推荐数据结构：

```ts
interface ReviewBoundaryItem {
  boundaryId: string
  leftSegmentId: string
  rightSegmentId: string
  frame: number
  status:
    | "unreviewed"
    | "confirmed"
    | "modified"
    | "flagged"
  confidence?: number
  reasons?: ReviewReason[]
}
```

底层仍可保留 segment 模型。

# 17. 中央主视觉：Boundary Frame Pair

切点判断最重要的信息不是参数，而是：

```text
Frame N      →      Frame N+1
```

因此 Boundary Frame Pair 应从右侧小面板提升为中央主视觉。

推荐：

```text
┌────────────────────────┐   ┌────────────────────────┐
│                        │   │                        │
│                        │   │                        │
│      前镜末帧          │ → │      后镜首帧          │
│                        │   │                        │
│                        │   │                        │
└────────────────────────┘   └────────────────────────┘

镜头 27                     镜头 28
00:24:17.000                00:24:17.042
```

默认不显示：

- Frame ID
- 原始 PTS
- 算法 score

这些进入“检测详情”。

# 22. 快捷键建议

复核模式应重新定义快捷键优先级。

| 快捷键 | 行为 |
|---|---|
| Space | 预览当前切点 |
| Enter | 确认当前切点并进入下一个 |
| ↑ / ↓ | 上 / 下一个待确认切点 |
| ← / → | 播放头 ±1 帧 |
| Shift + ← / → | ±5 帧 |
| Delete / Backspace | 删除当前切点 |
| S | 在播放头补切 |
| M | 标记稍后处理 |
| Cmd/Ctrl + Z | Undo |
| Cmd/Ctrl + Shift + Z | Redo |

其中：

> Enter 不再用于“当前帧切开”。

因为复核模式中最高频动作应该是“确认”，而不是“新增切点”。

# 39. Modal / Drawer / Inspector 使用规范

前处理必须与全局工作台采用同一套交互层级：

```text
核心长期任务 → Workspace
持续过程 → Workspace 内原地状态变化
持续配置 → Drawer / Sheet
当前对象详情 / 编辑 → Inspector
重要确认 → Modal
高频快速切换 → Dropdown / Popover
```

因此：

- 素材准备：Workspace
- 自动分镜扫描：Workspace 内原地进行
- 切分设置：Drawer / Sheet
- 检测详情：Inspector
- 完成素材准备：Modal
- 切分策略快速选择：Dropdown / Popover（如后续需要）

这样素材准备、逐镜分析和成果应用不会形成三套不同的交互语言。

# 42. Native Studio 视觉与交互继承

Preparation 不再维护独立视觉风格；颜色、材质、Panel geometry、motion、cursor、focus、overlay、Density 与 View Preference 全部由 `00-global/WORKSPACE_DESIGN_SYSTEM.md` V2 Native Studio 定义。

本 Workspace 只定义任务特有的组合：

- Import / Detection / Boundary Review 都发生在同一持续工作窗口内；
- Boundary Frame Pair、Viewer、Queue、Inspector、Timeline 使用可 resize/collapse 的共享 Panel system；
- Move / Split / Delete / Fine-tune 等结构操作优先 direct manipulation + source-anchored actions，并有 live preview / safe cancel；
- Detection / decode / save 是后台任务，不使用阻塞整个工作台的全屏 loading；
- Confirm / saving / saved / error / conflict 使用共享 state token 与明确文字/图标反馈；
- 桌面指针、键盘、Context Menu、Undo/Redo 是正式工作流，不是附加增强；
- 不得因为复用旧 Calibration UI 而恢复旧 palette、Card grammar 或页面级视觉主题。

素材准备必须始终遵守以下全局关系：

```text

   ▼

   │
   ▼
```

因此素材准备的完成条件不是“进入某个旧总览页”或“完成所有分析配置”，而是：

> **已经生成一套足够可靠、可以直接被逐镜分析工作台消费的镜头结构数据。**

素材准备完成以后：

- Scene 分组、剪辑节奏等宏观信息进入逐镜分析 Timeline；
- 分析模板进入逐镜分析的 Analysis Settings；
- AI 辅助进入逐镜分析的 Analysis Settings；
- 数据表、导出分享和创作转化都属于成果应用；
- 前处理不再承担这些职责。

不是：

```text
导入视频
↓
配置引擎
↓
看参数
↓
开扫描弹窗
↓
看候选 score
↓
应用结果
↓
进入校准器
↓
理解并操作独立校准模块
↓
编辑
↓
应用草稿
```

AisenLens 的核心体验应该从：

> **“这里有一套非常完整的视频分析能力，你来操作它。”**

转向：

> **“把视频给我，我先帮你整理好，然后我们开始分析。”**

---

# 49. 一句话设计原则总结

> **前处理不是一个功能集合，而是一条被系统主动引导完成的任务链。**

> **复核不是编辑优先，而是判断优先。**

> **用户语言在前，系统语言在后。**

> **正常状态安静，异常状态突出。**

> **持续过程页面化，配置抽屉化，详情 Inspector 化，重要确认 Modal 化。**

> **默认只展示当前决策真正需要的信息。**

> **素材准备只负责产生可靠镜头结构；分析数据生产交给逐镜分析，成果消费交给成果应用。**
