# AisenLens 成果应用 Workspace 架构

> 本文从原 Global 方案中抽取“成果应用”细节，成为数据表、导出分享和创作转化的唯一 Workspace Source of Truth。正式数据资格由 `../04-domain/analysis-data/ANALYSIS_DATA_MODEL.md` 决定；本 Workspace 只消费，不重新定义分析事实。

# 19. 成果应用 Workspace

推荐结构：

```text
成果应用

[ 数据表 ]   [ 导出与分享 ]   [ 创作转化 ]
```

这三个模块属于同一阶段，但复杂度足够大，可以继续作为成果应用内部二级页面。

---

# 20. 数据表

## 20.1 定位

数据表是：

> **分析数据的最终数据库视图。**

它应类似轻量 Airtable / Notion Database，而不是普通报告页面。

---

## 20.2 表格结构

前三列建议固定：

```text
镜号
分镜截图
时长
```

后面的字段动态来自当前 Analysis Template。

例如：

```text
┌────┬──────────┬────────┬────────┬────────┬──────────┬────────────┐
│镜号│ 分镜截图 │ 时长   │ 景别   │ 运镜   │ 构图     │ 色彩       │
├────┼──────────┼────────┼────────┼────────┼──────────┼────────────┤
│001 │ [frame]  │ 3.2s   │ 全景   │ 固定   │ 中心     │ 暖色       │
│002 │ [frame]  │ 2.1s   │ 中景   │ 推镜   │ 三分     │ 暖色       │
│003 │ [frame]  │ 1.7s   │ 特写   │ 固定   │ 中心     │ 冷色       │
└────┴──────────┴────────┴────────┴────────┴──────────┴────────────┘
```

Toolbar：


```text

```

例如：

```text
Scene 01   室内 / 夜

001
002

004
005
006
```

---

# 22. 数据表默认“查看优先”

成果应用阶段默认是消费数据。

因此建议：

默认：

> 查看模式

用户点击：

```text
编辑数据
```

以后才进入可直接修改字段的状态。

所有修改仍然写回同一份 canonical analysis data。

不要复制出第二份“导出数据”。

# 23. 导出与分享

由于需求复杂，不建议做成大型 Modal。

推荐：

> **Export Studio 独立页面**

布局：

```text
┌────────────────────┬───────────────────────────┬────────────────────┐
│                    │                           │                    │
│ 导出类型           │          PREVIEW          │ 导出设置           │
│                    │                           │                    │
│ ● 分析表格         │                           │ 显示字段           │
│                    │                           │ ✓ 景别             │
│ ○ 视频 + 分析表    │                           │ ✓ 运镜             │
│                    │                           │ ✓ 构图             │
│ ○ 分析水印视频     │                           │                    │
│                    │                           │ 样式               │
│                    │                           │ Dark / Light       │
│                    │                           │                    │
│                    │                           │ [ 导出 ]           │
└────────────────────┴───────────────────────────┴────────────────────┘
```

## 24.2 视频 + 分析表联动视频

建议重点建设成 AisenLens 的标志性能力。

例如：

```text
┌──────────────────────────┬────────────────────┐
│                          │ Shot 027           │
│                          │                    │
│          VIDEO           │ 景别   中景        │
```

适用于：

- 教学
- Film Study
- 课程
- 视频讲解
- B站 / YouTube
- Portfolio

# 27. 创作转化

## 27.1 定位

创作转化不是：

> “打开一个 Prompt 输入框生成 AI 视频。”

而是：

> **把分析成果转化成自己的创作方案。**

完整逻辑：

```text
看懂别人的作品
       ↓
提炼形式规律
       ↓
应用到新的创作目标
       ↓
生成可拍摄方案
```

---

# 28. 创作转化入口

例如：

```text
创作转化

基于分析结果创建新的创作方案。


从哪里开始？

[ 整部影片 ]

[ 一个场景 ]

[ 选中的镜头 ]

[ 一组分析特征 ]
```

用户选择参考范围以后，再选择：

```text
我想提取：

✓ 剪辑节奏
✓ 景别变化
✓ 运镜方式
○ 色彩
○ 声音
```

然后输入新的创作目标。

例如：

```text
我要拍一个 30 秒咖啡广告。
```

---

# 29. AI 在创作转化中的角色

AI 应该做：

> **方法迁移**

而不是内容复制。

例如从参考作品提取：

```text
平均镜头长度
3.1s

节奏
慢 → 快 → 慢

景别变化
全景 → 中景 → 特写

运镜规律
大多数使用固定机位，
情绪节点使用缓慢推镜
```

然后转化为新的拍摄方案：

```text
Shot 01
3.5s
全景
固定
建立咖啡店环境

Shot 02
2.4s
中景
缓慢推镜
人物拿起咖啡

Shot 03
1.8s
特写
固定
咖啡表面蒸汽
```

# 30. 创作成果的最终形态

推荐层级：

```text
创作方案
   ↓
Concept / Treatment
   ↓
Scene
   ↓
Shot List
   ↓
每个 Shot 的执行要求
```

每个 Shot 可以复用 AisenLens 已有分析结构：

```text
Shot 01

时长
3.2s

景别
中景

运镜
缓慢推镜

构图
中心构图

内容
人物坐在窗边

声音
环境声 + 杯子落桌

备注
动作完成后切镜
```

这会让：

```text
分析数据 Schema
```

与：

```text
创作 Shot Schema
```

天然形成闭环。

# 31. AI 视频生成未来的位置

未来如果增加 AI 视频：

不建议：

```text
创作
→ Prompt
→ 生成视频
```

而建议：

```text
创作方案
↓
Shot 07
↓
生成参考图
↓
生成动态预演
```

例如：

```text
Shot 07

[ 生成参考图 ]
[ 生成动态预演 ]
```

AI 视频的角色是：

> **Previs / 创作预演**

而不是 AisenLens 的核心产品身份。

# 32. 成果应用的数据消费契约（冻结）

1. 默认消费 **Confirmed Analysis Data**。
2. `AI Candidate` 未经显式采用不得进入正式成果列、正式导出或创作转化正式输入。
3. `stale` 数据可以展示，但必须显式标记并允许筛选；导出策略应让用户知道其复核状态。
4. 表格列、导出字段和创作转化输入都来自稳定 Field ID / Output Capability，而不是从 Inspector UI 结构反推。
5. 成果应用不成为 Canonical Analysis Data 的第二编辑源；需要修改正式分析时返回逐镜分析。
6. 任何导出预设只保存“如何消费/呈现数据”，不复制正式 Analysis Record。
