# AisenLens 全局工作台 UI / IA 设计方案

> 文档定位：AisenLens 全局产品信息架构与工作台 UI 设计基线  
> 适用范围：项目级工作台、逐镜分析工作台、成果应用区、全局导航与交互层级  
> 不包含：素材准备页的详细交互规范（另见独立《AisenLens 前处理工作台 UX/UI 设计方案》）

---

## 1. 设计目标

AisenLens 的核心不是“把很多视频分析功能放在一个软件里”，而是让用户沿着一条稳定、自然、专业的工作流完成：

**原始视频 → 可分析镜头 → 结构化分析数据 → 可展示 / 可分享 / 可继续创作的成果**

因此，全局 UI 不应继续按“功能模块”组织，而应围绕用户的工作阶段组织。

最终建议将项目内一级工作区收敛为三个：

1. **素材准备**
2. **逐镜分析**
3. **成果应用**

三者分别对应：

- 素材准备 = 数据输入与结构化准备
- 逐镜分析 = 数据生产
- 成果应用 = 数据消费、展示、输出与转化

---

# 2. 全局产品信息架构

推荐最终结构：

```text
AisenLens
│
└── 项目
    │
    ├── 素材准备
    │      └── 导入 → 智能切分 → 镜头复核
    │
    ├── 逐镜分析
    │      └── 单一分析工作台
    │             ├── 分析模板（设置）
    │             └── AI 辅助（设置）
    │
    └── 成果应用
           ├── 数据表
           ├── 导出与分享
           └── 创作转化
```

# 3. 为什么取消原来的「总览」

原有总览中的核心信息，例如：

- 剪辑节奏
- Scene / 场景分组
- 影片结构
- 镜头密度
- 时间结构

不应继续被设计成一个需要单独访问的“总览页”。

这些数据本质上都是：

> **沿着影片时间轴理解视频结构的辅助信息。**

因此应被吸收到逐镜分析工作台中的 Timeline。

未来 Timeline 不只是镜头时间线，而是 AisenLens 的“结构数据骨架”。

例如：

```text
时间
───────────────────────────────────────────────

Scene
┌──── Scene 01 ─────┐┌────── Scene 02 ───────┐

Shot
│01│02│03│04│05│06│07│08│09│

Rhythm
▂ ▃ ▅ █ ▆ ▃ ▂ ▂ █ ▇ ▄

Audio
~~~~~~~▃▅████▅▂~~~~~~~~

Marker
      ●                 ●

景别
LS────MS────CU──CU────LS────

运镜
固定────推────固定────摇────
```

这样用户不需要“去总览页看完再回来”，而是在真正分析的同时获得宏观结构。

- 素材准备
- 逐镜分析
- 成果应用

负责：

> **完成当前工作阶段的实际任务**

所有强交互都发生在这里。

# 5. 左侧导航的设计原则

三个一级入口不是一次性 Stepper，而是三个长期存在的 Workspace。

用户可以来回切换。

因此不要设计成：

```text
① 素材准备
   ↓
② 逐镜分析
   ↓
③ 成果应用
```

而应设计为：

```text
✓  素材准备

●  逐镜分析

   成果应用
```

含义：

- `✓`：已经达到可继续使用的状态
- `●`：当前所在 Workspace
- 普通状态：可访问但当前未选中

# 6. 三个一级工作区

---

# 6.1 素材准备

素材准备负责：

> 把原始视频变成可靠、可分析的镜头序列。

内部流程：

```text
导入素材
   ↓
智能切分
   ↓
镜头复核
   ↓
准备完成
```

原来的“准备”和“校准”合并为同一个 Workspace。

产品层不再出现独立一级“校准”。

详细页面设计另见：

**《AisenLens 前处理工作台 UX/UI 设计方案》**

---

# 6.2 逐镜分析

逐镜分析是整个 AisenLens 的核心工作区。

它应该是用户使用时间最长、最稳定的页面。

核心任务只有一个：

> **观察镜头，并形成结构化分析数据。**

因此逐镜分析只保留一个主页面：

**分析工作台**

不再将：

- 分析模板
- AI 辅助

提升成和分析工作台同级的页面。

它们属于：

> **改变分析工作台行为的配置。**

---

# 6.3 成果应用

成果应用负责：

> 使用已经完成的分析数据。

主要包含：

1. 数据表
2. 导出与分享
3. 创作转化

逻辑顺序：

```text
查看成果
   ↓
发布 / 分享成果
   ↓
把成果转化为新的创作方案
```

# 8. 分析工作台的四个区域

## 8.1 左侧：影片结构导航器

回答：

> **我现在正在分析什么？**

不只是普通 Shot List。

建议支持：

```text
按镜头
按场景
按标签
```

例如：

```text
全部镜头

Scene 01
  001
  002
  003

Scene 02
  004
  005
  006
```

Scene 是镜头的组织方式，不再拥有独立页面。

---

## 8.2 中央：观察对象

核心永远是 Video。

负责：

- 播放
- Seek
- 当前 Shot 定位
- 截图
- 必要的视觉辅助
- 构图 Overlay 等

中央区不应该充斥分析表单。

---

## 8.3 右侧：Analysis Inspector

回答：

> **当前镜头的数据是什么？**

所有由分析模板定义的字段都在这里。

例如：

```text
Shot 027

景别
[ 中景 ▾ ]

摄影机运动
[ 缓慢推镜 ▾ ]

构图
[ 中心构图 ▾ ]

光线
[ 柔和侧光 ]

色彩
[ 暖色 / 低饱和 ]

声音
[ 环境声 ]

备注
[                         ]
```

这里是用户生产分析数据的主要位置。

---

## 8.4 底部：多轨 Timeline

回答：

> **当前镜头处在影片的什么结构中？**

未来 Timeline 可以逐步承载：

- Scene Track
- Shot Track
- Rhythm Track
- Audio Track
- Annotation Track
- Template Field Tracks

它会逐渐成为整个产品最重要的结构可视化组件。

# 11. 模板编辑方式

不建议使用小型 Modal。

模板配置未来会越来越复杂，包括：

- 字段增删
- 字段排序
- 字段类型
- 字段选项
- 字段说明
- 默认值
- AI 是否参与
- 校验逻辑

推荐：

> **大型右侧 Drawer / Sheet**

宽度：

```text
560px ~ 680px
```

例如：

```text
分析工作台                       ┌────────────────────────────┐
                               │ 分析设置                ×  │
                               │                            │
                               │ [分析模板] [AI辅助]        │
                               │                            │
                               │ 当前模板                   │
                               │ 电影语言                   │
                               │                            │
                               │ 分析字段                   │
                               │                            │
                               │ ☰ 景别                     │
                               │ ☰ 构图                     │
                               │ ☰ 摄影机运动               │
                               │ ☰ 光线                     │
                               │ ☰ 色彩                     │
                               │ ☰ 声音                     │
                               │                            │
                               │ + 添加字段                 │
                               │                            │
                               │                保存        │
                               └────────────────────────────┘
```

这样用户的心理仍然是：

> “我在调整当前工作台。”

而不是：

> “我离开了分析工作。”

# 12. 模板与 Timeline 的关系

模板字段未来可以选择映射为 Timeline Track。

例如模板定义：

```text
摄影机运动
```

Timeline 可以显示：

```text
摄影机运动

固定────────摇────固定────推──────
```

模板定义：

```text
景别
```

Timeline：

```text
景别

LS────MS────CU──CU────LS────────
```

最终形成：

```text
Template
   ↓
定义数据
   ↓
Analysis Workspace
   ↓
产生数据
   ↓
Timeline
   ↓
显示时间结构
```

# 13. AI 辅助的产品定位

AI 同样不应该是独立页面。

AI 是：

> **分析工作台中的辅助能力。**

因此：

```text
AI Settings
=
控制 AI 如何参与

Analysis Inspector
=
真正消费 AI 分析结果
```

# 14. AI 状态入口

Toolbar：

```text
✦ AI 建议
```

或者：

```text
✦ AI · 8
```

含义：

- 灰色：AI 关闭
- Accent：AI 开启
- `AI · 8`：有 8 个 AI 建议等待确认

点击以后打开：

```text
分析设置
```

并进入 AI 辅助 Tab。

# 15. 统一「分析设置」

推荐将模板和 AI 统一进：

> **分析设置 Drawer**

内部：

```text

       └── Analysis Settings
```

# 17. AI 设置应该关注人与 AI 的权责关系

默认不要把这些工程参数放在核心 UI：

```text
Model
Temperature
Prompt
Top P
```

真正重要的是：

- AI 可以分析哪些字段
- AI 是否直接写入
- 是否需要人工确认
- 是否覆盖人工数据
- 如何处理低可信结果
- 是否保留 AI 来源
- 是否批量分析

模型参数可以放入：

> 专家设置

# 20. 数据表

## 20.1 定位

数据表是：

> **分析数据的最终数据库视图。**

它应类似轻量 Airtable / Notion Database，而不是普通报告页面。

---

## 20.2 表格结构

前三列建议固定：

```text
镜号
分镜截图
时长
```

后面的字段动态来自当前 Analysis Template。

例如：

```text
┌────┬──────────┬────────┬────────┬────────┬──────────┬────────────┐
│镜号│ 分镜截图 │ 时长   │ 景别   │ 运镜   │ 构图     │ 色彩       │
├────┼──────────┼────────┼────────┼────────┼──────────┼────────────┤
│001 │ [frame]  │ 3.2s   │ 全景   │ 固定   │ 中心     │ 暖色       │
│002 │ [frame]  │ 2.1s   │ 中景   │ 推镜   │ 三分     │ 暖色       │
│003 │ [frame]  │ 1.7s   │ 特写   │ 固定   │ 中心     │ 冷色       │
└────┴──────────┴────────┴────────┴────────┴──────────┴────────────┘
```

# 22. 数据表默认“查看优先”

成果应用阶段默认是消费数据。

因此建议：

默认：

> 查看模式

用户点击：

```text

```

以后才进入可直接修改字段的状态。

所有修改仍然写回同一份 canonical analysis data。

不要复制出第二份“导出数据”。

# 27. 创作转化

## 27.1 定位

创作转化不是：

> “打开一个 Prompt 输入框生成 AI 视频。”

而是：

> **把分析成果转化成自己的创作方案。**

完整逻辑：

```text
看懂别人的作品
       ↓
提炼形式规律
       ↓
应用到新的创作目标
       ↓
生成可拍摄方案
```

---

# 28. 创作转化入口

例如：

```text
创作转化

基于分析结果创建新的创作方案。


从哪里开始？

[ 整部影片 ]

[ 一个场景 ]

[ 选中的镜头 ]

[ 一组分析特征 ]
```

用户选择参考范围以后，再选择：

```text
我想提取：

✓ 剪辑节奏
✓ 景别变化
✓ 运镜方式
○ 色彩
○ 声音
```

然后输入新的创作目标。

例如：

```text
我要拍一个 30 秒咖啡广告。
```

---

# 29. AI 在创作转化中的角色

AI 应该做：

> **方法迁移**

而不是内容复制。

例如从参考作品提取：

```text
平均镜头长度
3.1s

节奏
慢 → 快 → 慢

景别变化
全景 → 中景 → 特写

运镜规律
大多数使用固定机位，
情绪节点使用缓慢推镜
```

然后转化为新的拍摄方案：

```text
Shot 01
3.5s
全景
固定
建立咖啡店环境

Shot 02
2.4s
中景
缓慢推镜
人物拿起咖啡

Shot 03
1.8s
特写
固定
咖啡表面蒸汽
```

---

# 30. 创作成果的最终形态

推荐层级：

```text
创作方案
   ↓
Concept / Treatment
   ↓
Scene
   ↓
Shot List
   ↓
每个 Shot 的执行要求
```

每个 Shot 可以复用 AisenLens 已有分析结构：

```text
Shot 01

时长
3.2s

景别
中景

运镜
缓慢推镜

构图
中心构图

内容
人物坐在窗边

声音
环境声 + 杯子落桌

备注
动作完成后切镜
```

这会让：

```text
分析数据 Schema
```

与：

```text
创作 Shot Schema
```

天然形成闭环。

# 31. AI 视频生成未来的位置

未来如果增加 AI 视频：

不建议：

```text
创作
→ Prompt
→ 生成视频
```

而建议：

```text
创作方案
↓
Shot 07
↓
生成参考图
↓
生成动态预演
```

例如：

```text
Shot 07

[ 生成参考图 ]
[ 生成动态预演 ]
```

AI 视频的角色是：

> **Previs / 创作预演**

而不是 AisenLens 的核心产品身份。

# 33. 全局 UI 层级原则

建议全产品统一：

### Workspace

用于：

> 长时间完成核心任务。

例如：

- 素材准备
- 逐镜分析
- 数据表
- Export Studio
- 创作转化

---

### Drawer / Sheet

用于：

> 调整当前 Workspace 的持续配置。

例如：

- 分析模板
- AI 辅助
- 切分设置
- 显示字段

---

### Inspector

用于：

> 编辑当前对象。

例如：

- 当前 Shot 分析
- 当前 Boundary
- 当前导出样式

---

### Modal

用于：

> 短暂且明确的重要决策。

例如：

- 新建模板
- 删除模板
- 完成复核
- 确认覆盖
- 导出前确认

---

### Dropdown / Popover

用于：

> 高频快速切换。

例如：

- 切换模板
- 切换 Scene
- 选择字段
- 设置单个字段值

# 34. 交互语言原则

## 34.1 Workspace 是“工作的地方”

不要每有一个复杂功能就新建页面。

---

## 34.2 Settings 是“改变工作方式的地方”

分析模板与 AI 都属于工作台设置。

---

## 34.3 正常状态安静，异常状态突出

例如：

正常：

```text
✓ 已保存
```

异常：

```text
⚠ 保存失败    重试
```

---

## 34.4 用户语言优先于工程语言

优先：

```text
AI 建议
切分策略
分析模板
镜头复核
完成素材准备
```

避免主 UI 中大量出现：

```text
Preset ID
Detector
Threshold
Task Snapshot
Media Identity
Apply Calibration Draft
```

# 35. 视觉信息密度原则

判断一个信息是否常驻，可以问：

> **用户当前做决策是否需要这个信息？**

如果不需要，应：

- 隐藏
- 折叠
- 移入 Drawer
- 移入 Inspector
- 移入专家设置

# 37. 推荐的产品定位表达

最终 AisenLens 不再是：

> 一个集合了自动切镜、分析、AI、表格、导出、创作等工具的软件。

而应该呈现为：

> **一套从视频理解到创作转化的专业工作流。**

完整链路：

```text
视频
↓
镜头
↓
分析数据
↓
可视化成果
↓
可分享成果
↓
可执行创作方案
```

这套架构的最大价值是：

**未来功能继续增加时，一级导航仍然不需要变化。**

任何新能力都可以很自然地判断应该属于：

- 数据输入
- 数据生产
- 数据消费

从而保证 AisenLens 的产品结构长期保持稳定。
