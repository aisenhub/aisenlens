# 视频与音频媒体管线计划

## 目标

在本地浏览器内导出带分析信息的视频，并为后续导入音频、录音和多轨混音提供同一条时间线管线。视频预览保持使用原生 `HTMLVideoElement`；媒体解析、离线取帧、音频解码和导出编码使用 Mediabunny。

## 已完成

- 视频关联时解析容器级时长、显示尺寸、平均帧率与音轨状态。
- 已有关联项目在首次打开时补齐缺失的元数据。
- Mediabunny 动态加载，避免进入编辑器时增加主包负担。
- 项目持久化模型已切换为媒体素材集合、主视频素材 ID 与显式多音频轨；文件句柄按素材 ID 保存。
- 已提供导入音频和录音 Blob 素材的服务边界，以及含入点、时长、增益、静音、淡入淡出的离线混音计划。
- 已接入音频导入、浏览器录音、轨道静音/音量控制和 Web Audio 预览调度。
- 已接入多音频轨时间轴：显示真实峰值波形，支持片段移动与首尾裁剪，拖动结束后持久化编辑结果。
- 已接入淡入淡出拖拽手柄、播放头内片段分割和音频轨上/下重排；淡化参数同时用于实时预览和离线混音。
- 时间轴帧带已迁移为 Mediabunny `CanvasSink` 离线解码，继续使用项目派生缓存。
- 分镜首帧、尾帧和用户指定的导出代表图已统一为 Mediabunny `CanvasSink` 精确取帧；代表图仅在启用“导出构图”时绘制构图辅助。
- 已建立无副作用的视频图层 Canvas 渲染器：分析信息复用既有 ViewModel，构图复用既有几何绘制；截图已接入该组合器，未来预览和导出可按相同顺序调用。
- 已建立 Worker 视频导出内核：主线程读取项目素材、构造逐分镜图层并离线混合主视频/项目音频，Worker 逐帧解码、Canvas 合成、编码和封装；支持 MP4/WebM 能力协商、阶段进度、取消和 Blob 结果。
- 已接入“导出 → 导出分析视频”弹窗：在导出前保存当前项目，展示浏览器实际可用的 MP4/WebM 编码器，并提供分辨率、码率、画面分析、构图蒙版、项目音频和原声混合设置；完成后直接下载，取消不会作为失败提示。
- 已加入零依赖浏览器导出集成测试：`npm.cmd run test:video-export` 启动 Vite 和无头 Chrome，使用 `test/test.mov` 实际解码、合成分析/构图图层，逐个编码浏览器支持的 MP4/WebM 容器，并重新解析成品以校验尺寸、时长、进度和音轨。
- 导出 Worker 不再强制硬件编码偏好，确保编码器能力探测结果与实际 `VideoSampleSource` 配置一致，避免“格式可选但启动导出失败”。
- 项目音轨的离线混音以 planar PCM 传入 Worker，并由 `AudioSampleSource` 分块编码；测试同时覆盖生成的 WAV 项目音轨和首帧后的取消任务。

## 当前边界

- 视频加载、格式兼容性、解码会话和可变帧率处理的后续实施，统一遵循 `docs/VIDEO_LOADING_OPTIMIZATION_PLAN.md`；该计划不改变本文件定义的原生预览与 Mediabunny 离线处理边界。
- 音频轨按导入时刻创建单个片段，后续将扩展声像、关键帧和音频效果。
- 支持 File System Access API 的浏览器会在导出开始时选择保存位置；Worker 通过 Mediabunny `StreamTarget` 分块回传，主线程持续写入文件并确认每次写入，不会生成完整输出 Blob。其他浏览器继续使用 Blob 下载。

## 未来计划：长视频导出优化

### P0：分段音频混音与编码

- 当前文件输出已流式写盘，但离线混音仍会先生成整段 `AudioBuffer` 和 planar PCM；长视频、多轨或高采样率项目仍可能占用大量内存。
- 将导出音频改为固定时长窗口（建议 20–30 秒）处理：仅解码与当前窗口相交的素材片段、在窗口内应用增益/静音/淡入淡出，再立即编码并释放该窗口 PCM。
- 窗口边界必须使用项目全局时间戳，保持音频连续；淡入淡出跨越窗口时按原始片段时间计算，不允许出现音量跳变、重叠或空洞。
- 视频逐帧解码与音频窗口编码仍由同一个导出时钟协调；不引入录屏或实时播放作为导出降级路径。

### P0：流式写入可靠性与内存上限

- 保持“Worker 编码分块回传 → 主线程文件流写盘 → Worker 确认后继续”的单一写入路径；文件句柄不能进入 `postMessage`。
- 为分块传输增加可观测指标：已写字节数、待确认分块数、最近写入吞吐和写入耗时；默认 4 MiB 分块只作为起点，后续依据真实长视频测试调整。
- 明确写入失败语义：权限撤销、磁盘/配额错误或文件流关闭时停止编码并调用 `abort()`；正常完成必须调用 `close()`，取消不得把半成品当作成功结果。
- 所有来自 Worker 的分块数据必须以可转移 `ArrayBuffer` 传递并在确认后释放，不在主线程拼接任何完整输出缓冲区。

### P1：导出任务状态与用户反馈

- 将导出任务状态标准化为准备、混音、音频编码、视频编码、封装、写盘完成、已取消和失败，避免取消、写入错误与 Worker 错误互相覆盖。
- 在进度界面显示当前帧进度、累计写入大小和阶段说明；只在可可靠取得数据时展示耗时或预计剩余时间，不伪造磁盘剩余空间预测。
- 导出开始时冻结项目快照和导出设置，避免用户在导出中编辑分镜、蒙版或音频轨导致成片内容不确定。
- 成功后提示已写入所选位置；用户取消保存位置不显示失败提示；不可恢复的编码、权限或写入错误需给出可执行的重试建议。

### P1：导出能力、质量与内容扩展

- 继续以实际编码器能力协商作为 MP4/WebM 可选项依据；不静默更换容器或编码器，失败信息需指出受限的能力。
- 增加可保存的质量预设，统一控制分辨率、帧率、码率和音频码率；以后再根据设备性能提供明确标注的低负载预设。
- 为未来字幕、片头片尾、品牌标识和额外分析图层保留固定的 Canvas 合成顺序，并确保每个图层仍为无副作用的纯渲染函数。
- 音频编辑后续按独立优先级扩展声像、自动化关键帧和效果器；这些能力必须同时进入实时预览和分段离线导出，不能形成两套声音结果。

### P1：验证与压力测试

- 保留现有短素材浏览器集成测试，用于验证 MP4/WebM、蒙版、音频、取消和流式结果不生成 Blob。
- 新增不提交大型二进制素材的长时长压力测试：使用可生成的测试媒体或受控夹具，覆盖 10 分钟、30 分钟、多轨、连续淡化和低写入吞吐场景。
- 对流式目标分别测试普通 `WritableStream` 和实际 File System Access API 的人工验收流程；验证保存对话框、取消、权限错误、文件关闭与成片可重新解析。
- 记录峰值内存、写入吞吐、总耗时和取消响应时间，并把可接受阈值写入测试说明；优化前后以同一夹具对比，不凭主观感受调整分块大小。

### 明确不做

- 不为长视频回退到屏幕录制、实时播放抓取、服务端上传转码或把完整输出重新汇聚为 Blob。
- 不承诺浏览器无法可靠提供的磁盘剩余空间、断点续导或中断后继续封装；若未来需要断点恢复，应单独设计可恢复的分段容器与项目级任务持久化。
- 不引入多套导出内核：浏览器下载回退与文件系统保存只允许在最终目标不同，编码、合成、取消和能力协商必须共用同一 Worker 管线。

## 架构边界

| 层级 | 责任 | 不承担 |
| --- | --- | --- |
| `features/media` | 文件引用、容器探测、解码能力、帧与音频读取、派生缓存键 | 编辑器 UI、分镜业务规则 |
| `features/timeline` | 视频主轨与音频轨的时间、裁剪、静音、增益、淡入淡出 | 解码与编码实现 |
| `features/video` | 原生预览、时间轴帧带、当前帧交互 | 导出编码时钟 |
| `features/export` | 导出预设、分析图层渲染、离屏视频/音频合成、下载 | 项目持久化 |

## 目标数据模型

现有单一 `ProjectMedia` 将替换为项目媒体库和显式时间线引用，不保留双轨数据模型：

```text
Project
├── mediaAssets[]
│   ├── primary-video
│   ├── imported-audio
│   └── recorded-audio
├── primaryVideoAssetId
└── audioTracks[]
    └── clips[] { assetId, startFrame, inFrame, durationFrames, gainDb,
                  muted, fadeInFrames, fadeOutFrames }
```

视频分析分镜继续引用主视频时间，不复制视频或截图数据。音频轨只存素材引用和编辑参数；二进制继续由本地文件句柄管理。录音先落为浏览器 `Blob`，再注册成 `recorded-audio` 素材。

## 分阶段实施

### 1. 媒体基础层

- 将视频元数据探测收敛到 `mediaProbeService`：使用 `Input`、主视频/音频轨和 `computePacketStats()`。
- 以媒体指纹和派生版本作为缓存键；源文件变化时失效帧带、波形和导出预览。
- 建立可取消的 `CanvasSink` 帧解码器，替换时间轴、首尾帧和代表截图中分散的 `seek + canvas`。
- 原生视频仅保留播放、拖动预览和用户直接交互；不再作为离线帧处理实现。

### 2. 音频素材与多轨时间线

- 新增音频导入与浏览器录音素材；两者与主视频使用同一 `MediaAsset` 模型。
- 轨道编辑第一期提供放置、裁剪、静音、音量、淡入淡出和删除；后续再加声像、关键帧和效果。
- 预览播放使用短窗口调度，避免一次解码整部视频；时间轴拖动停止音频并在定位后重新调度。
- 离线导出使用 `OfflineAudioContext` 按轨道混音，统一采样率、声道数与响度上限。

### 3. 分析视频图层

- 从现有内容蒙版解析器派生纯数据的 `VideoOverlayFrame`，不能依赖 DOM 截图。
- 图层组合器按导出帧的时间接收当前分镜、模板字段、时间码和布局；视频导出阶段负责为每帧构造该输入。
- 构图蒙版是独立可选图层；内容蒙版、构图蒙版和未来字幕按固定 `z-index` 合成。
- 每个图层必须是无副作用的 `render(context, frame)`，供预览、导出预览和最终编码复用。

### 4. Worker 视频导出

- 导出使用 Worker：`CanvasSink` 解码主视频，离屏 Canvas 合成图层，`VideoSampleSource` 编码，`AudioSampleSource` 将主线程离线混音得到的 PCM 分块写入音轨，`Output` 封装；编辑器入口、设置弹窗、进度、取消和下载已接入。
- 初始预设为 MP4 和 WebM；实际编码器由 `getFirstEncodableVideoCodec()` 协商，不将浏览器支持情况写死。
- 单源视频音频与所有项目音频轨进入同一个离线混音结果，再编码进输出容器。
- 提供取消、阶段进度、编码能力错误和平台适配的保存方式：支持 File System Access API 时使用流式目标，其他浏览器使用 Blob 下载；长文件在流式路径中不会完整常驻内存。

### 5. 导出体验与验证

- 将现有“导出”弹窗拆成“报告”和“分析视频”两种入口，视频导出先提供时长、画布、帧率、内容图层和音频开关。
- 首次导出前显示实际可用格式和编码器；失败时说明具体不支持的容器或编码，而不是静默降级。
- 已完成视频图层、可用 MP4/WebM 容器、项目音频编码、取消与 Worker 流式目标的浏览器端集成测试；后续补充时间映射、音频裁剪/淡化与长视频内存占用的定向测试。

## 实施顺序

1. 完成媒体资产与缓存模型替换。
2. 接入 `CanvasSink` 取帧并移除分散的离线视频元素。
3. 实现音频素材、录音、轨道编辑与预览调度。
4. 实现可复用的分析 Canvas 图层。
5. 实现 Worker 导出、格式预设和导出弹窗。

在第 5 步前不实现临时视频导出按钮或实时录屏降级方案，避免未来的真实合成管线被一次性实现锁死。
