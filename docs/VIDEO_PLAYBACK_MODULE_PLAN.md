# 真实视频播放与媒体信息模块拆分计划

## 目标

将编辑器从固定 `160` 秒演示播放切换到用户关联视频的原生播放状态。此阶段不实现真实波形、帧带、截图、自动切镜或分镜持久化。

| 阶段 | 落点 | 工作 | 状态 |
| --- | --- | --- | --- |
| V1 | `features/editor/hooks/useVideoPlayback.ts` | 统一原生视频引用、播放、定位、速率、时长和事件同步 | [x] |
| V2 | `VideoPreviewCanvas`、`VideoPlaybackControls` | 接入真实视频节点和控制命令 | [x] |
| V3 | `EditorTimeline`、`EditorWorkspace` | 以真实时长绘制刻度、定位和分镜比例 | [x] |
| V4 | `EditorWorkspace` | 用项目媒体元数据替换演示视频信息 | [x] |
| V5 | 验证 | 生产构建及实际视频手动验证 | [~] |

## 约束

- 浏览器原生 `<video>` 是唯一播放时间来源，禁止 `setInterval` 模拟播放。
- 当前阶段帧率未知时仅以 `24 fps` 作为逐帧步进显示回退；不得伪造精确帧号。
- 波形和胶片帧带仍为临时视觉占位，后续由独立媒体处理模块替换。

## 参考项目取舍

- 借鉴 OpenReel：播放控制器与 UI 桥接层分离、统一的播放/暂停/定位/速率命令、事件驱动的时间同步，以及开始拖动→轻量预览→结束拖动后正式定位的流程。
- 借鉴 OpenCut：播放状态集中管理，时间使用领域时间值；不同界面通过订阅读取状态，不各自维护计时器。
- 不照搬 OpenReel 的 `AudioContext` 主时钟、音视频漂移补偿和渲染帧调度。它服务于多轨合成编辑器；AisenLens 当前只有一条原始视频，原生 `<video>` 的 `currentTime` 和媒体事件更可靠、更简单。
- 后续帧引擎可在 `requestVideoFrameCallback` 可用时获取实际呈现帧信息；在此之前，帧率不明的视频不能宣称精确逐帧定位。

## 实施记录

- 已新增 `useVideoPlayback`，以原生 `<video>` 事件同步播放、暂停、定位、速率、时长与当前时间，移除编辑器的 `setInterval` 演示计时。
- 预览、控制条与时间线已共享同一视频播放状态；时间线按真实媒体时长定位和绘制刻度。
- 视频信息改为项目媒体元数据；真实视频加载后初始化一条连续的“未分析”镜头，不再注入演示影片分镜。
- 波形与帧带仍为视觉占位，自动切分按钮仍是临时演示，待后续独立模块替换。
- 已执行 `pnpm.cmd run build`，通过；真实视频交互需要在支持 File System Access API 的 Chrome/Edge 中手动验证。
- 播放状态已扩展为加载、就绪、定位、播放、暂停、结束与错误；预览区显示加载/定位反馈，并在媒体错误时提供重新加载入口。
- 支持时使用 `requestVideoFrameCallback` 同步实际呈现画面时间，原有 `timeupdate` 保留为回退；不以页面计时器推进视频时间。
- 时间轴播放头拖动期间以浏览器快速定位能力同步原生视频，提供实时画面预览；松开后再提交最终的精确位置。上一/下一分镜控制同时选择并跳转到目标分镜首帧。
