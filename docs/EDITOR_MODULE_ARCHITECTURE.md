# AisenLens 专业编辑器模块架构

> 2026-08-12 更新：项目与媒体、真实播放、手动分镜、模板、截图、标记、真实帧带、真实音频波形和可恢复自动分镜均已完成。自动分镜当前仅生成可审阅的本地硬切候选，应用结果仍需用户确认。

## 目标

编辑器采用本地优先架构：视频、截图、项目内容与未来的 AI 推理输入默认保留在用户设备中。界面组件不直接承担媒体处理、存储或 AI 调用；每项能力都可以独立演进或替换。

在数据结构确认前，本文件只定义模块职责与依赖边界，不定义数据库表、持久化格式或具体字段。

## 分层

```text
编辑器协调层
├── 领域模块：项目、分镜、分析、注释、模板、截图、导出
├── 本地能力层：媒体、帧图、波形、缓存、本地存储
└── 智能能力层：任务、模型适配、结果解析、人工确认
```

### 编辑器协调层

负责组织工作流、编辑器布局、当前选择与短暂交互状态。它调用领域模块和能力层，但不保存业务数据，也不实现媒体或 AI 算法。

### 领域模块

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| `project` | 项目元信息、项目设置、本地备份与恢复 | 本地存储 |
| `media` | 项目关联的本地媒体来源及其元信息 | 媒体能力 |
| `shots` | 手动/自动识别的镜头段、顺序、入点、出点与标记 | 媒体、帧图 |
| `analysis` | 景别、运镜、构图、色彩、声音、节奏等结构化分析 | 分镜、模板、AI（可选） |
| `annotations` | 镜头或时间点的自由笔记、标签与重点记录 | 分镜、截图 |
| `templates` | 分析维度定义、字段配置与项目使用的模板快照 | 无 |
| `screenshots` | 关键帧、手动截图、缩略图及其镜头关联 | 媒体、帧图、本地存储 |
| `groups` | 分场、段落、序列等镜头组织方式 | 分镜 |
| `export` | 项目包、报告、截图与结构化数据的导出 | 项目、分镜、分析、注释 |

### 本地能力层

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| `media-engine` | 本地媒体读取、播放定位、元数据解析与兼容性诊断 | 项目业务规则 |
| `frame-engine` | 帧级定位、缩略图和截图生成、帧缓存 | 分镜分析结论 |
| `waveform-engine` | 音频解码、波形与节奏特征生成 | 时间线 UI |
| `storage` | 本地项目持久化、二进制资源索引、自动保存、备份序列化 | React 状态 |
| `workers` | 后台执行耗时解析、缓存和未来本地 AI 工作 | 页面渲染 |

### 智能能力层

AI 是辅助来源而非项目事实的唯一来源。所有 AI 结果都必须可查看、可编辑、可确认，并与原始推理任务分开保存。

| 模块 | 职责 |
| --- | --- |
| `ai-orchestrator` | 任务创建、进度、取消、重试与资源调度 |
| `ai-adapters` | 本地模型、用户自带 Key 的远程模型，以及未来平台云端的统一适配 |
| `ai-analysis` | 场景切分、镜头描述、语音转写、镜头语言建议等任务定义 |
| `ai-results` | 结果解析、置信度、溯源与人工确认状态 |

第一阶段仅开发本地引擎与用户自带 Key 云端；平台云端只保留适配接口和数据枚举，不建设平台侧 GPU、任务队列、额度或计费服务。

用户自带 Key 必须经过独立的密钥仓库与服务适配器访问：React 页面、Zustand 普通设置、项目 JSON、任务记录和备份包都不得持有或序列化密钥。

## 依赖规则

```text
templates ───────────────┐
media → shots → analysis ├→ export
          ├→ annotations │
          └→ screenshots ┘

media-engine / frame-engine / waveform-engine / storage / workers
  仅被领域模块通过服务接口调用，不依赖 UI 组件。

ai-orchestrator → ai-adapters → ai-analysis → ai-results → analysis
```

- `project` 是聚合根，其他领域数据都通过项目关联。
- `media` 只描述本地媒体来源，不承担分镜或分析数据。
- `shots` 是分析、注释、截图和分组的共同时间基准。
- `templates` 保存字段定义；项目必须保存所用模板的快照，避免模板后来修改导致历史项目语义变化。
- UI 临时状态只放在编辑器协调层或 Zustand store，不能作为项目数据持久化。
- AI、媒体和存储能力只能通过明确服务接口访问，禁止在 React UI 中直接实现。

## 数据结构基础规范

- 核心项目文件使用带版本号的 JSON 结构，并为每次结构变化提供迁移策略。
- 视频、截图、波形、缩略图和帧缓存等二进制或可再生资源不得嵌入核心项目 JSON。
- 运行时对象（`File`、`Blob`、`HTMLVideoElement`、音频缓冲、Object URL、播放位置与滚动位置）不得直接写入项目数据。
- 媒体必须拥有稳定 ID、元数据和本地文件指纹；重新打开项目时，文件不可用应进入“待重新关联”状态，而不是丢失关联数据。
- 所有镜头边界和时间点的内部精确基准应使用帧编号；仅在播放或展示时转换为秒和时间码，避免浮点累计误差。
- 本地存储需要分别管理项目数据、媒体资源、派生缓存和用户界面偏好，并在未来增加配额检查与清理策略。
- 详细实体、关系、导出包络与逐模块确认清单见 `docs/EDITOR_DATA_STRUCTURE.md`。

```text
├── features/

```

### 项目与媒体交互规则

- 项目库卡片展示稳定封面、标题、镜头数、批注数与最后编辑时间；仅在异常时额外显示“未关联视频”“视频待重新关联”或“格式不支持”的媒体状态。
- 搜索匹配项目名称、描述和文件夹名称；排序支持最近编辑、创建时间与镜头数。文件夹删除仅使项目回到未分类，不删除项目。
- 新建项目名称可为空，自动命名为“未命名拉片项目”；可选择文件夹，也可在创建时选择本地视频。视频不复制、不上传，只读取元数据与指纹后保存关联。
- 创建弹窗提供“创建空项目”和“创建并进入编辑器”；选择并成功读取视频后，后者显示为“创建并开始拉片”。读取失败或格式不支持时不创建媒体关联，并保留重新选择入口。
- 没有关联视频的编辑器只能展示项目级内容与“添加本地视频”空状态，不展示伪造时间线、镜头或播放数据；关联成功后才初始化媒体相关工作流。
- 媒体引用失效时，保留全部项目内容并显示“视频待重新关联”。重新选择文件只有指纹完全匹配时才恢复关联；指纹不一致时不得静默替换，提示用户以该视频新建项目。视频替换与帧范围迁移留待单独设计。
- 删除项目时展示将清除的项目数据、截图和用户主动托管副本的数量与体积；默认删除全部项目本地数据，但绝不删除仅被引用的用户原始视频文件。
