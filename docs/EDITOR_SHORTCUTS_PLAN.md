# 编辑器快捷键方案

## 目标

让有 Premiere Pro、DaVinci Resolve 或其他专业剪辑软件经验的用户，能够在 AisenLens 的单视频拉片工作流中自然地完成定位、观看、拆分与标记；不把它伪装成多轨剪辑器。

本方案以“动作”而不是组件事件为中心：一个动作只能有一个实现入口，可以拥有多个等价快捷键。快捷键帮助、左侧快捷键面板、设置弹窗和实际监听器均从同一注册表读取。

## 调研结论

- 专业剪辑软件共同的高频核心是 `Space`、`J / K / L`、逐帧、编辑点跳转、`I / O` 和 `M`；这些键位优先于品牌自己的工具键位。
- OpenReel 将快捷键定义为带分类、默认键、当前键与动作 ID 的注册表，并提供 Premiere、Resolve 等预设。它的默认传输键包括 `Space`、方向键、`J / K / L`、`Home / End`、`[` / `]` 与 `M`。
- OpenCut 将动作定义、键位持久化和全局捕获监听拆开；监听器在输入框、弹窗、加载或录制状态下不触发，并通过 `Escape` 取消当前交互。
- 旧 AisenLens 已证明在此产品中 `Space`、`,` / `.`、方向键、`Enter` 和 `Ctrl/Cmd + S` 的可发现性；但它把“分镜截图”放在 `Enter`，与当前已确认的“分镜拆分”语义冲突，不能沿用。

Adobe 与 Blackmagic 的官方文档页面在本次网络环境中超时，未将未验证的厂商专属键位作为方案依据；本方案只采纳上述跨软件稳定惯例，并以本地参考项目的 Premiere / Resolve 预设交叉校验。

## 键位总表

### 第一阶段：立即实现

| 分类 | 键位 | AisenLens 动作 | 说明 |
| --- | --- | --- | --- |
| 传输 | `Space` | 播放 / 暂停 | 全局最高优先级。 |
| 传输 | `J` / `K` / `L` | 倒放预览 / 暂停 / 正放预览 | 连按 `J`、`L` 在 `0.5× → 1× → 2×` 间切换；倒放用帧步进调度实现，不能把 `video.playbackRate` 设为负数。 |
| 定位 | `←` / `→`、`,` / `.` | 后退 / 前进一帧 | 两组等价键，兼容方向键习惯与旧项目。执行前暂停。 |
| 定位 | `Shift + ←` / `Shift + →` | 后退 / 前进 5 帧 | 以项目帧率换算，不使用固定秒数。 |
| 定位 | `↑` / `↓` | 跳到上一个 / 下一个分镜边界 | 对应专业剪辑中的上一个 / 下一个编辑点。 |
| 定位 | `Home` / `End` | 跳到视频首帧 / 尾帧 | `End` 定位到最后可显示帧，而非超出视频时长。 |
| 分镜 | `Enter` | 在播放头处分镜拆分 | 已由产品确认；播放头必须位于当前分镜内部，边界处不执行。 |
| 标记 | `M` | 添加“重要镜头”标记 | 使用现有四类标记模型；创建后选中该标记，但不抢走用户当前面板。 |
| 交互 | `Esc` | 取消当前拖拽 / 绘制 / 选择 | 只取消临时操作；不清空已保存的分镜或标记。 |
| 帮助 | `?` | 打开快捷键帮助 | 与左侧快捷键入口共用同一弹层。 |

### 第二阶段：在边界编辑验证后实现

| 键位 | AisenLens 动作 | 采用条件 |
| --- | --- | --- |
| `[` | 将当前分镜起点对齐播放头 | 播放头必须位于当前分镜内，且不会把前一分镜压缩到零帧。 |
| `]` | 将当前分镜终点对齐播放头 | 播放头必须位于当前分镜内，且不会把后一分镜压缩到零帧。 |
| `Ctrl/Cmd + K` | 分镜拆分（Premiere 迁移别名） | 与 `Enter` 指向同一动作，不改变已确认的主键位。 |
| `F` | 全屏预览切换 | 仅编辑器获得焦点时触发，不覆盖浏览器 `F11`。 |
| `0` | 预览适应画布 | 仅预览画布处于活动工作区时触发。 |
| `=` / `-` | 时间轴放大 / 缩小 | 仅时间轴处于活动工作区时触发；保留 `Ctrl/Cmd + 滚轮`。 |

### 第三阶段：先建立能力，后开放键位

| 动作 | 拟定键位 | 当前不开放的原因 |
| --- | --- | --- |
| 全局撤销 / 重做 | `Ctrl/Cmd + Z`、`Ctrl/Cmd + Shift + Z`、`Ctrl + Y` | 目前只有构图绘制拥有局部历史，分镜、标记、分组和字段编辑没有统一历史。 |
| 删除当前分镜并合并 | `Delete` / `Backspace` | 该操作会改变分镜结构，必须先接入可撤销历史与明确的合并方向。 |
| 设置入点 / 出点 | `I` / `O` | 当前没有独立“选区”领域模型；不能把它们误做成分镜边界。 |
| 立即保存 | `Ctrl/Cmd + S` | 项目目前依赖自动持久化；需先提供可等待完成的显式保存动作与保存状态。 |
| 播放速度档位 | `1`–`6` | 先完成 `J / K / L` 的连续播放体验，避免裸数字与未来工具、字段编辑冲突。 |

## 交互边界

1. 当焦点在 `input`、`textarea`、`select`、`contenteditable`、按钮或可编辑时间码时，除 `Escape` 的失焦处理外，不执行编辑器全局快捷键。
2. 对话框、下拉菜单、导出、模板编辑和自动分镜运行期间，快捷键注册表整体暂停；弹层自己的键盘交互优先。
3. 全局键位和“活动工作区”键位分开。传输、定位、拆分和标记不要求焦点；时间轴缩放、预览缩放只在对应工作区活动时触发，避免劫持浏览器行为。
4. 所有时间操作以帧为单位并钳制到 `[0, lastFrame]`；每次定位后同步播放头、当前分镜和分镜列表。
5. 操作无效时不抛错、不改变选择；只在需要解释时给出一次轻量提示。

## 实施结构

新增 `src/features/editor/shortcuts/`，不再在 `EditorWorkspace`、`EditorTimeline` 等组件中各自监听 `keydown`：

- `definitions.ts`：动作 ID、默认键位、分类、适用范围与帮助文案。
- `normalize.ts`：统一 `Ctrl` / `Cmd`、键盘布局、组合键与输入控件判断。
- `useEditorShortcuts.ts`：唯一的 capture-phase 监听器，将动作分派给工作区提供的回调。
- `ShortcutHelpDialog.tsx`：从注册表分组显示真实可用键位；第一期不做用户自定义。

第一期将移除现有 `EDITOR_SHORTCUTS` 与 `LiteSettingsModal` 中的静态重复列表，迁移当前 `Enter` 和构图蒙版的独立监听器。构图蒙版的 `Delete` / `Backspace` 与局部撤销保留为“蒙版编辑范围”动作，优先级高于全局动作。

用户自定义、导入导出与 Premiere / Resolve 键位预设只在核心动作稳定、全局历史完成后加入；此时沿用 OpenCut 的冲突校验与持久化模式，但不引入预设切换造成的多套默认行为。
